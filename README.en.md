## 📝 Project Description

This checkout is Ren2Hub. Start with the [local documentation](docs/README.md) for its current routing, admission, API and release contracts. The upstream project introduction and attribution are retained. Deployment follows the [Ren2Hub installation guide](docs/installation/DOCKER.md); upstream images do not contain this checkout's changes. Ren2Hub uses single-process FIFO admission and requires sequential version replacement.

Billing uses the wallet balance, with an additional Token quota limit. Site subscriptions and plan management have been removed; historical billing records remain protected. See the [billing architecture](docs/billing/IMPLEMENTATION.md) for the current billing contract.

> [!NOTE]  
> This is an open-source project developed based on [One API](https://github.com/songquanpeng/one-api)

> [!IMPORTANT]  
> - This project is intended solely for lawful and authorized AI API gateway, organization-level authentication, multi-model management, usage analytics, cost accounting, and private deployment scenarios.
> - Users must lawfully obtain upstream API keys, accounts, model services, and interface permissions, and must comply with upstream terms of service and applicable laws and regulations.
> - Users should ensure their use complies with upstream terms of service and applicable laws and regulations.
> - When providing generative AI services to the public, users should comply with applicable regulatory requirements and fulfill all filing, licensing, content safety, real-name verification, log retention, tax, and upstream authorization obligations required by their jurisdiction.

## 🚀 Quick Start

Build this Ren2Hub checkout using the [single-instance Docker guide](docs/installation/DOCKER.md). It builds the Go backend and Vue frontend from source, with PostgreSQL and Redis. Configure the required secrets before starting. The application binds to `127.0.0.1:3000`; containers have no CPU or memory quotas.

## ✨ Key Features

> For detailed features, please refer to [Features Introduction](https://docs.newapi.pro/en/docs/guide/wiki/basic-concepts/features-introduction)

### 🎨 Core Functions

| Feature | Description |
|------|------|
| 🎨 New UI | Vue 3 and TypeScript application built with Vite; see the [frontend guide](frontend/README.md) |
| 🌍 Multi-language | Vue interface: Simplified Chinese and English |
| 🔄 Data Compatibility | SQLite, MySQL and PostgreSQL; upgrades follow the local migration and release contract |
| 📈 Data Dashboard | Visual console and statistical analysis |
| 🔒 Permission Management | Token grouping, model restrictions, user management |

### 💰 Authorized Usage Accounting and Billing

- ✅ Internal top-up and quota allocation for lawful authorized scenarios (EPay, Stripe)
- ✅ Organization-level per-request, usage-based, and cache-hit cost accounting
- ✅ Cache billing statistics for OpenAI, Azure, DeepSeek, Claude, Qwen, and supported models
- ✅ Flexible billing policies for internal management or authorized enterprise customers

### 🔐 Authorization and Security

- Password login and optional 2FA in the Vue interface
- Short-lived Bearer access tokens, HttpOnly refresh cookies, and revocable device sessions
- OAuth account binding and account security controls; module availability comes from the backend
- The Vue login page offers password, Passkey and configured OAuth sign-in according to the backend settings; see the [authentication contract](docs/authentication.md)

### 🚀 Advanced Features

**API Format Support:**
- ⚡ [OpenAI Responses](https://docs.newapi.pro/en/docs/api/ai-model/chat/openai/create-response)
- ⚡ [OpenAI Realtime API](https://docs.newapi.pro/en/docs/api/ai-model/realtime/create-realtime-session) (including Azure)
- ⚡ [Claude Messages](https://docs.newapi.pro/en/docs/api/ai-model/chat/create-message)
- ⚡ [Google Gemini](https://doc.newapi.pro/en/api/google-gemini-chat)
- 🔄 [Rerank Models](https://docs.newapi.pro/en/docs/api/ai-model/rerank/create-rerank) (Cohere, Jina)

**Intelligent Routing:**
- ⚖️ Channel weighted random
- 🔄 Automatic retry on failure
- 🚦 User-level model rate limiting

**Format Conversion:**

Chat, Responses, Claude and Gemini use the shared conversion planner. Supported tools, media, citations, termination semantics and explicit rejection boundaries are maintained in the [protocol support matrix](docs/routing/GATEWAY_SUPPORT_MATRIX.md).

## 🚢 Deployment

Use the maintained [Compose configuration](docker-compose.yml) and [installation guide](docs/installation/DOCKER.md). Frontend development uses [docker-compose.dev.yml](docker-compose.dev.yml); panel users can read [the BT notes](docs/installation/BT.md). Upstream New-API images do not include this checkout's changes.

Ren2Hub admission belongs to one process. Drain and exit the old gateway before starting the new one, following the [release and rollback procedure](docs/routing/GATEWAY_RELEASE.md). Preserve the existing PostgreSQL, Redis and application volumes; do not use rolling replicas.

Environment variables are in [.env.example](.env.example), and authentication follows the [session contract](docs/authentication.md). FIFO limits and retry budgets follow the [gateway API](docs/routing/GATEWAY_API.md) and [unified routing](docs/routing/UNIFIED_ROUTING.md). Redis retains its provider, frequency, health and cache duties, but no longer owns user/channel concurrency.
