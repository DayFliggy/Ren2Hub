# 移动端待办

范围是 Ren2Hub 前端在 ≤767px（Tailwind `md` 断点以下）的交互、组件、样式与视觉回归覆盖，判定基准是[主题与样式结构](THEMES.md)。路径相对 `frontend/`，行号是登记时的定位，不代表当前代码行号。本页只列还没处理的项，条目修复并验证后直接删除。

共享层已有的基础：页面滚动锁统一走 `modalStack` 计数，控制台 `scroll-zone` 带 `overscroll-behavior: contain`；筛选、日期、标签和字段菜单的浮层经 `useFloatingPanel` Teleport 到 body，按视口夹取并在空间不足时向上翻转；`.touch-target` 在 <640px 把命中区透明扩展到 44px；手机导航在字体就绪后重新定位当前项。对应的保护用例是 `tests/visual/mobile-touch-targets.spec.ts`、`responsive-breakpoints.spec.ts`、`navigation-fonts.spec.ts` 和 `style-compatibility.spec.ts`。

自动化用的是 Playwright 的 Chromium 和 WebKit 运行时，不是真机 Safari：没有执行真实软键盘、安全区设备、读屏器和低端 GPU 帧率的测量，合成事件不等同于 iOS/Android 物理输入法，缩小视口也不代表软键盘弹起。iOS Safari 上 `overflow: hidden` 对橡皮筋和滚动链的效果、软键盘弹起时浮层的重新定位、`ChipPicker` 在物理输入法下的 blur 与选词时序都还要真机确认。生产构建的检查不能由开发模式代替。

## 建议顺序

1. 共享层收口：`ConsoleModal` 聚焦时按 `visualViewport` 调整高度；批量操作栏 sticky；`ConsoleToggle` 焦点光晕。
2. DataTable 方案：先接 `useTableScrollFade` 与常显滚动条（低成本），再决定是否做 `card` 模式；`TicketsView` 随方案补移动形态。
3. 首页：`touch-action` 改回 `pan-y` 并重设进入手势；Canvas 补 DPR 分档、`pageshow` 恢复与 `visualViewport` 监听。
4. 页面级清理：栅格断点、公共页 `svh`、认证页键盘与 Turnstile、其余令牌与样式项。
5. 补齐视觉回归：在 `mobile-touch-targets.spec.ts` 基础上扩成通用 44px 断言、320/360 视口、内层溢出断言、输入字号断言、非 reduced 动画用例。
