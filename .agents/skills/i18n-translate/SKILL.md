# Vue 前端翻译

## 适用范围

本技能用于 Ren2Hub 当前 `frontend/`。只读审阅只检查并报告；用户要求添加或修复文案时，完成范围内修改与验证，不额外请求常规编辑批准。

先读取项目 `AGENTS.md` 中的 i18n 规则，再从调用处追踪实际消息来源。当前使用 `vue-i18n`、`useI18n()` 和稳定语义键，支持 `en`、`zh-CN`。

- `frontend/src/i18n/index.ts` 定义语言及分域加载。
- `frontend/src/i18n/locales/{en,zh-CN}/` 保存 `common`、`home`、`auth`、`console`、`lab`、`setup` 消息模块。
- 部分功能在 `frontend/src/i18n/` 的共享 TypeScript 文件中保存两种语言的消息。沿用调用处正在使用的来源，不另建副本。

## 修改流程

1. 从 Vue 组件、调用参数和已有消息核对键、业务含义、插值及展示位置。用户明确指定的产品文案可作为来源；不要把任务说明或审阅意见误当作界面文案。
2. 直接编辑现有 TypeScript 消息来源，补齐受影响键在 `en` 与 `zh-CN` 中的对应内容；保留无须修改的既有值。无需生成临时写入脚本，也不要求旧 `web/` 目录、七语言 JSON 文件或 `i18n:sync` 命令。
3. 新键放入所属领域，沿用已有嵌套结构和命名。保持 `common`、`home` 首包与其他领域懒加载的边界，不为单项修复重排或迁移全部语言包。
4. 核对所有受影响调用、两种语言及占位符，再按项目规则运行适用验证。

一个缺失键也使用同样的语义和双语言检查，但不触发全库翻译补全。若任务只是审阅，不执行上述写入步骤。

## 文案与一致性

- 根据已有 UI 和用户意图起草自然、简洁的文案。仅在无法从上下文解决的业务语义会实质影响正确性时询问；继续不依赖答案的已授权工作。
- 保留 Vue I18n 的 `{name}` 等插值名称、复数和消息链接语法；两种语言的参数应与调用处一致。
- 保留品牌、模型名、API 路径、URL 和技术标识；明确请求新增的产品文案按其指定含义翻译。
- 按按钮、标题、提示、错误或空态分别选择语气，并考虑中英文长度和容器空间。不能仅凭译文与英文相同就认定未翻译。
- 不将对话中的凭据、生产数据或诊断内容写入语言包。

## 验证与完成

从 `frontend/` 运行与改动相关的既有测试，并按 `AGENTS.md` 的适用顺序执行类型、lint、格式与构建检查。涉及 UI 呈现时遵循其 Playwright 验证要求，检查实际消息解析、插值和布局。

先检查 `frontend/package.json` 中真实存在的命令。缺少检查条件时，记录具体原因和未验证项，继续独立工作；不要为了满足旧技能安装另一套前端工具或伪造验证成功。按请求交付审阅结果或已验证的修改，并遵循工作区同步规则。
