## 📝 プロジェクト説明

このチェックアウトは Ren2Hub です。現在のルーティング、受付制御、API、リリース契約は[ローカルドキュメント](docs/README.md)を参照してください。上流プロジェクトの紹介と帰属情報を保持しています。配置には [Ren2Hub 導入手順](docs/installation/DOCKER.md)を使用してください。上流イメージにはこのチェックアウトの変更は含まれません。Ren2Hub は単一プロセスのローカル FIFO を使用し、新旧バージョンを順番に切り替えます。RenAI ワークスペースでは専用の配置設定と PostgreSQL を使用します。

課金はウォレット残高を使用し、Token の利用上限も適用します。サイトのサブスクリプションとプラン管理は削除済みで、過去の課金データは保護されています。専用コミットと検証範囲は[検証記録](docs/routing/SINGLE_INSTANCE_ACCEPTANCE.md)を参照してください。

> [!IMPORTANT]
> - 本プロジェクトは、合法的に許可された AI API ゲートウェイ、組織レベルの認証、マルチモデル管理、利用量分析、コスト管理、プライベートデプロイのシナリオのみを対象としています。
> - ユーザーは、上流の API キー、アカウント、モデルサービス、インターフェース権限を合法的に取得し、上流のサービス利用規約および適用される法律法規を遵守する必要があります。
> - ユーザーは、利用方法が上流のサービス利用規約および適用される法律法規に準拠していることを確認してください。
> - 生成 AI サービスを公衆に提供する場合、ユーザーは適用される規制要件を遵守し、管轄区域で求められる届出、ライセンス、コンテンツセキュリティ、本人確認、ログ保持、税務、上流認可などのすべての義務を履行してください。

## 🚀 クイックスタート

現在の Ren2Hub ソースは[単一インスタンスの Docker 導入手順](docs/installation/DOCKER.md)に従って構築してください。Go バックエンドと Vue フロントエンドをビルドし、PostgreSQL と Redis を使用します。必要なシークレットを設定してから起動します。公開先は `127.0.0.1:3000` のみで、コンテナに CPU やメモリの上限を設定しません。

## ✨ 主な機能

> 詳細な機能については[機能説明](https://docs.newapi.pro/ja/docs/guide/wiki/basic-concepts/features-introduction)を参照してください。

### 🎨 コア機能

| 機能 | 説明 |
|------|------|
| 🎨 新しいUI | モダンなユーザーインターフェースデザイン |
| 🌍 多言語 | Vue UI は簡体字中国語と英語をサポート |
| 🔄 データ互換性 | SQLite、MySQL、PostgreSQL に対応。更新はローカルの移行・リリース契約に従います |
| 📈 データダッシュボード | ビジュアルコンソールと統計分析 |
| 🔒 権限管理 | トークングループ化、モデル制限、ユーザー管理 |

### 💰 認可済み利用量とコスト管理

- ✅ 合法的に許可されたシナリオでの内部チャージとクォータ割り当て（EPay、Stripe）
- ✅ 組織レベルのリクエスト単位、使用量ベース、キャッシュヒットのコスト会計
- ✅ OpenAI、Azure、DeepSeek、Claude、Qwen などのモデルのキャッシュ課金統計
- ✅ 内部管理または認可済み企業顧客向けの柔軟な課金ポリシー

### 🔐 認証とセキュリティ

- 😈 Discord認証ログイン
- 🤖 LinuxDO認証ログイン
- 📱 Telegram認証ログイン
- 🔑 OIDC統一認証
- 🔍 Key使用量クォータ照会（[new-api-key-tool](https://github.com/Calcium-Ion/new-api-key-tool)と併用）



### 🚀 高度な機能

**APIフォーマットサポート:**
- ⚡ [OpenAI Responses](https://docs.newapi.pro/ja/docs/api/ai-model/chat/openai/create-response)
- ⚡ [OpenAI Realtime API](https://docs.newapi.pro/ja/docs/api/ai-model/realtime/create-realtime-session)（Azureを含む）
- ⚡ [Claude Messages](https://docs.newapi.pro/ja/docs/api/ai-model/chat/create-message)
- ⚡ [Google Gemini](https://doc.newapi.pro/ja/api/google-gemini-chat)
- 🔄 [Rerankモデル](https://docs.newapi.pro/ja/docs/api/ai-model/rerank/create-rerank)（Cohere、Jina）

**インテリジェントルーティング:**
- ⚖️ チャネル重み付けランダム
- 🔄 失敗自動リトライ
- 🚦 ユーザーレベルモデルレート制限

**フォーマット変換:**

Chat、Responses、Claude、Gemini は共通の変換プランナーを使用します。ツール、メディア、引用、応答の終了状態と明示的な拒否条件は[対応表](docs/routing/GATEWAY_SUPPORT_MATRIX.md)を参照してください。

**Reasoning Effort サポート:**

<details>
<summary>詳細設定を表示</summary>

**OpenAIシリーズモデル:**
- `o3-mini-high` - 高思考努力
- `o3-mini-medium` - 中思考努力
- `o3-mini-low` - 低思考努力
- `gpt-5-high` - 高思考努力
- `gpt-5-medium` - 中思考努力
- `gpt-5-low` - 低思考努力

**Claude思考モデル:**
- `claude-3-7-sonnet-20250219-thinking` - 思考モードを有効にする

**Google Geminiシリーズモデル:**
- `gemini-2.5-flash-thinking` - 思考モードを有効にする
- `gemini-2.5-flash-nothinking` - 思考モードを無効にする
- `gemini-2.5-pro-thinking` - 思考モードを有効にする
- `gemini-2.5-pro-thinking-128` - 思考モードを有効にし、思考予算を128トークンに設定する
- Gemini モデル名の末尾に `-low` / `-medium` / `-high` を付けることで推論強度を直接指定できます（追加の思考予算サフィックスは不要です）。

</details>

## 🚢 デプロイ

保守対象の [Compose 設定](docker-compose.yml)と[導入手順](docs/installation/DOCKER.md)を使用してください。フロントエンド開発には [docker-compose.dev.yml](docker-compose.dev.yml)、管理パネルには[宝塔の説明](docs/installation/BT.md)を参照してください。上流 New-API イメージには、このチェックアウトの変更は含まれません。

Ren2Hub の同時実行枠は単一プロセスが管理します。旧ゲートウェイの処理完了と終了を確認してから新ゲートウェイを起動します。[リリースとロールバック手順](docs/routing/GATEWAY_RELEASE.md)に従い、ローリング更新や複数レプリカを使用しないでください。PostgreSQL、Redis、アプリの既存データボリュームを維持します。

環境変数は [.env.example](.env.example)、認証は[セッション契約](docs/authentication.md)、FIFO と共有リトライ予算は[ゲートウェイ API](docs/routing/GATEWAY_API.md)と[統合ルーティング](docs/routing/UNIFIED_ROUTING.md)を参照してください。Redis は Provider 制限、頻度、ヘルス、キャッシュを担当し、ユーザーとチャネルの同時実行枠は管理しません。
