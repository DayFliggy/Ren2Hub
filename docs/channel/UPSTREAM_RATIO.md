# 渠道上游倍率

渠道列表中的“上游倍率”展示上游声明的分组倍率，便于管理员比对成本。它只读展示，不写入 `channel_ratio`，不参与路由，也不影响计费。

## 渠道识别

| 类型                                                  | 识别结果      | 说明                                     |
| ----------------------------------------------------- | ------------- | ---------------------------------------- |
| 59                                                    | `sub2api`     | 调度自动探测                             |
| 60                                                    | `newapi`      | 调度自动探测                             |
| 1、14、24、48、20、15、17、25、26、31、35、40、43、45 | `detect`      | 主流协议，需管理员点击“识别上游”后才探测 |
| 多 Key 渠道及其他类型                                 | `unsupported` | 只能手动填写倍率                         |

`detect` 只包含正常转发时把保存的 Key 全部内容作为凭据发给渠道地址的类型（OpenAI 兼容类型用 `Authorization: Bearer`，Anthropic 用 `x-api-key`，Gemini 用 `x-goog-api-key`，百度 v1 在请求头里同样带整串 Key；火山引擎的对话发送整串 Key，语音合成把 `appid|token` 拆开发送，两段都发给渠道地址），识别请求改用 Bearer 发送也不会把 Key 交给原本收不到它的地址。智谱 v3（16，由 `id.secret` 生成 JWT）、讯飞（18，用 `appid|secret|key` 签名连接地址）、腾讯（23，复合 Key 走 TC3 签名）和百度 v2（46，只把第一段作为 Bearer，`appid` 另放请求头）由复合 Key 派生凭据，按 `unsupported` 处理，不发送任何请求。

官方域名（如 `api.openai.com`、`api.anthropic.com`、`generativelanguage.googleapis.com`、`api.x.ai`、`openrouter.ai`、`aliyuncs.com`、`volces.com`、`siliconflow` 系列等）直接判为 `unsupported/official_api`，不发送任何请求。

## 探测

探测地址保留渠道地址中的部署前缀，只去掉末尾的 `/v1` 或 `/v1beta`。请求统一使用 `Authorization: Bearer <渠道 Key>`。

- Sub2API：请求 `/v1/sub2api/billing`，读取分组倍率、用户倍率、解析后倍率和高峰规则。`effective_ratio` 按当前时间计算高峰。Sub2API 只在订阅类型（`subscription`）分组上应用高峰倍率；管理员为用户单独设置的分组倍率会体现在解析后倍率里，Sub2API 对它缓存 30 秒。
- NewAPI：请求 `/api/usage/token/` 取得令牌名，再匿名请求 `/api/pricing` 取得分组和 `group_ratio`。`auto` 分组不参与关联。

HTTP 客户端每次探测新建，禁止跟随重定向，超时 10 秒。所有拨号都经过 SSRF 受保护拨号器，包括渠道配置的代理地址：开启防护时，代理主机按解析后的 IP 检查，内网与回环地址被拒绝。走代理时目标由代理远端连接，选用代理前仍按同一套 SSRF 规则校验目标 URL，被禁止的地址不会经代理发出；开启“对域名应用 IP 过滤”时目标域名在本机解析检查，这一步与共享受保护客户端一样不受探测 context 约束，代理远端的解析结果也无法核对。目标或代理主机是带 zone 的 IPv6 字面量（如 `fe80::1%eth0`）时直接拒绝，目标在拼探测地址时检查（记为 `invalid_base_url`），代理在拨号时检查：共享的 `common/ssrf_protection.go` 把这类地址当域名处理，未开启域名 IP 过滤时会放行，这个问题与上游 NewAPI 相同，留在共享代码中未改。同一渠道的探测串行执行，避免并发写回产生版本冲突。响应体有大小上限（普通接口 64 KB，定价页 4 MB），超出即失败。错误原因只用固定代码，不含上游原文或 Key。读取代理设置时只解析渠道 `setting`，JSON 损坏记为 `invalid_proxy`，不调用会清空并写回设置的原生 `GetSetting`。

## 分组关联

NewAPI 渠道按令牌名与分组名做严格相等比对，大小写和首尾空格都要一致。匹配成功记为 `name_match`。找不到时状态为 `needs_mapping`，管理员可在弹窗中手动选择分组，记为 `manual`。手动关联优先于名称匹配，并在后续探测中保留。管理员取消手动关联时，先清空旧分组的倍率，再用已缓存的分组列表按令牌名重新匹配：匹配成功显示对应倍率，匹配不到则状态为 `needs_mapping`。当前处于探测失败状态时保持失败状态，等下一次探测再更新。

定价页需要登录或被关闭（NewAPI 选项 `HeaderNavModules` 中 `pricing.requireAuth` 为真时返回 401，`pricing` 为 false 时返回 403）时状态为 `failed`，原因 `pricing_auth_required`，来源保持 `newapi`。

## 状态与过期

状态包括 `ok`、`needs_mapping`、`unsupported`、`auth_failed`、`rate_limited`、`failed`。失败时保留上一次成功的倍率，不延长有效期，并保留旧的指纹，因此渠道配置变化后旧值显示为过期。首次探测就失败、还没有任何旧倍率和明细时，直接记录当前指纹，不显示过期。NewAPI 定价页的解析结果超过 65535 字节（MySQL `TEXT` 上限）时，探测记为 `failed/detail_too_large`，不截断保存。

记录保存渠道 Key、类型和地址的指纹。渠道的 Key、地址、代理或类型变化后，指纹不一致，列表显示“已过期”。变化后第一次探测成功时，旧的自动倍率和名称匹配按本次结果重算，手动关联保留。渠道改成 Sub2API 或 NewAPI 固定类型时，只要旧明细不属于该类型（包括中途改成不支持类型、来源已被清空的情况），旧来源的明细、分组关联和自动倍率直接清空，不按新来源解读；手动倍率保留。自动倍率超过 `fresh_until` 也显示“已过期”。

## 调度

系统任务 `channel_upstream_ratio` 每分钟运行一次，在存在到期渠道或孤儿记录时启用。到期选择不按渠道启用状态过滤：尚无记录的 59/60 类型渠道以及已到期的自动记录，即使渠道已禁用，也可能继续使用该渠道 Key 发起倍率探测。禁用中继渠道不等同于停止这项展示探测；探测仍受下述来源、网络防护和退避规则约束。每轮先删除孤儿记录（渠道已删除，或渠道已用同一 ID 重建），再最多处理 20 个渠道，并发 4。只重探已识别出来源的渠道，`detect` 且尚无来源的渠道不进入到期列表。失败后按连续失败次数翻倍退避：第 1 次失败按 30 分钟间隔（±5 分钟抖动）重探，之后每次翻倍，最长 24 小时；`Retry-After` 更长时按它执行，同样不超过 24 小时。成功后恢复 30 分钟间隔。unsupported 的间隔放大 8 倍。

## 接口

| 方法 | 路径                                      | 权限              | 说明                                                                                                 |
| ---- | ----------------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------- |
| GET  | `/api/channel/upstream_ratios?ids=`       | `channel.read`    | 批量读取，最多 500 个；`with_groups=true` 只允许一个 ID，返回 NewAPI 分组列表。ETag 未变时返回 304。 |
| POST | `/api/channel/:id/upstream_ratio/refresh` | `channel.operate` | 立即探测，主流协议渠道在这里识别类型。                                                               |
| PUT  | `/api/channel/:id/upstream_ratio`         | `channel.write`   | 请求体只接受 `mode`、`ratio`、`group_name`、`version`，拒绝未知字段。                                |

手动模式下 `ratio` 为 0 到 1000 之间的十进制数，最多 18 位小数，十进制指数在 -18 到 18 之间。自动模式下 `group_name` 为空串表示取消手动关联。从手动切回自动时清空手填值，并让调度尽快重探。

写入使用 `version` 做比较并交换。版本冲突返回 409，前端重新加载记录。渠道在保存前被修改返回 409。参数错误返回 400，渠道不存在返回 404。

## 数据

表 `channel_upstream_ratios` 以 `channel_id` 为主键，每个渠道最多一条记录。记录同时保存所属渠道的创建时间：渠道删除后用同一 ID 重建时，创建时间不同，旧记录视为不存在，读取不展示，第一次写入时替换，调度也会清理。写回时还要求记录的渠道代次与事务内锁定的渠道一致，重建前发起的探测或保存在写回时返回 409，不会覆盖新渠道的记录。同一秒内删除并重建的渠道无法区分，仍由指纹判断是否过期。`ratio` 保存字符串形式的十进制，避免浮点误差。`detail` 保存 Sub2API 账单或 NewAPI 分组的原始解析结果，供弹窗展示。
