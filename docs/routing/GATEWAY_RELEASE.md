# 安装与更新的边界

只有一个 Ren2Hub 应用实例承接业务。源码发布、隔离候选验证和正式替换分别执行；本地测试或文档更新不表示正式实例已经切换。具体的服务器动作遵循所属工作区的同步流程与部署技能。

普通更新保留同一数据库、Redis、配置、密钥、附件和在途任务。先用旧、新两个固定镜像完成跨版本的隔离候选，再按更新技能做单实例替换；不重建数据，不让新旧实例同时接流量。

新安装使用空数据库、空的 Redis 编号和独立的附件目录，不导入其他核心的数据。程序在 AutoMigrate 前拒绝含 `billing_schemas`、`billing_events` 或业务 group 字段的数据库（`model/install_guard.go`），遇到这种库时停止，不原地转换、不清空。代码不内置模型价格，新安装的模型价格列表为空，在定价页配置后模型才可调用。

回退必须同时匹配代码、数据库和 Redis：迁移不可逆的版本不能只把旧镜像接回新库。恢复备份是独立的数据操作，需要明确批准。没有完成的验证和回退限制写进发布记录。
