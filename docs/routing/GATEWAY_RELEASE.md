# 单实例网关切换与回退

当前只允许一个网关进程承接业务流量，不支持新旧版本双活，也不含 Redis 用户/渠道并发后端。本文是发布契约；复验方法见[网关验证步骤](GATEWAY_VALIDATION.md)和[账务复验](../billing/VALIDATION.md)，验收边界见[网关验收边界](SINGLE_INSTANCE_ACCEPTANCE.md)。实际运行版本和验收结果只由所属工作区服务器档案维护。

## 发布前记录

记录源码 SHA、前端构建、不可变镜像身份、当前运行版本、配置及数据备份、回退版本。根据目标环境核对尚未执行的检查；本地构建或模拟测试通过不能替代该目标环境的发布验收。

现行账务使用 schema 5 的 `billing_schemas` 标记，只接受空库初始化或版本、`EvidenceKeyID` 均匹配的数据库。价格合同为 4，计算版本为 `newapi-c71eefbc-v1`。必须显式配置稳定 `CRYPTO_SECRET` 并保留对应密钥备份；它用于加密求值证据，不能在更新时随机替换。没有旧账务数据库升级路径；发现旧库会拒绝启动，既不迁移也不清空。首次采用此格式须使用经授权的新数据库，并保留原数据库及备份。之后同格式变更仍需检查各次 schema 与业务兼容性。

## 持久化兼容边界

| 数据 | 发布与回退必须核对 |
| --- | --- |
| 账务格式与资金事件 | `billing_schemas` 版本、BIGINT 资金投影、不可变事件、操作幂等及账户版本；旧资金写入程序不能访问当前库 |
| 价格和在途请求 | 唯一模型配置、独立工具 option、Quote、Usage、Charge、真实 attempt、加密求值证据、预留及发送保护不能丢失；恢复须用匹配密钥重放，不能重新取价或把未知消费自动释放 |
| 消费结果投递 | 资金提交、统计、SQL/ClickHouse 日志的恢复边界保持；日志写入不明不等于可以重复扣款或盲目重写 |
| 易支付 | 订单快照、商户版本、网关交易号唯一性与独立结算开关；新版本无主动查单，回退不得恢复不兼容 worker |
| Token 与准入配置 | `safe/allow/strict`、显式 0/false、覆盖继承和配置版本；仅缺失默认字段可补齐 |
| 渠道和原生状态 | 稳定凭据、端点身份、健康 epoch、探测所有权、状态摘要及 Token 归属保持，不补造未知身份 |
| 异步任务 | 原任务所有权、凭据与冻结报价保持；已接受任务不因本地失败被重放或自动释放 |
| 能力快照 | 宿主合同 v12，按指纹重建投影；旧快照不得开放不可执行协议 |

迁移入口为 `model/main.go`、`model/billing_schema.go` 与相关领域模型。JSON SQL 数据必须兼容目标 SQLite/MySQL/PostgreSQL 驱动；一个数据库通过不能推及其他数据库。回退应保留当前在途账务状态的等价保护，不能仅凭旧程序能忽略新增列就判断兼容。

## 顺序切换

1. 完成所需验证和备份，前后端作为同一版本发布。遵守所属工作区同步与部署流程；根仓库记录的子模块提交须已能从授权远端取得。
2. 停止旧进程接收新请求并排空。默认期限 120 秒，另留 5 秒强制取消后的清理时间；容器停止宽限应更长并保留依赖关闭时间。HTTP、SSE 和 hijacked WebSocket 都必须结束。
3. 确认旧进程已退出、没有其他业务副本写入。若实际来源版本使用旧 Redis 并发租约，再执行下节限定清理；当前本地准入版本间更新不需要该历史迁移步骤。
4. 使用经过兼容核验的数据库和配置启动新进程。核对 API/前端、认证、网关运行态 `schema_version=2`、配置版本冲突、JSON/SSE/Realtime、满载拒绝及账务烟测。
5. 核对授槽减释放等于活动数、等待已退登、账务恢复与投递积压正常，再记录发布结果。异常长持槽用于诊断，不强行清零。

Provider RPM/TPM、逻辑频率和健康探测使用各自存储。未设置 `REDIS_CONN_STRING` 时，Provider RPM/TPM 使用进程内有界预留（见[统一路由](UNIFIED_ROUTING.md#provider-额度预留)），重启后计数清零，因此同样只适用于单进程；启用逻辑频率限制但没有 Redis 时请求返回 503 `rate_limit_unavailable`，不改用内存计数；健康探测状态保存在主数据库。本地并发成功不代表依赖 Redis 的其他边界也可用。

## 旧 Redis 键清理

仅适用于从 Redis 并发租约版本切换的已授权操作。旧 `route:lease:v2:*` 部分占用 ZSET 没有 TTL。`cmd/gateway-lease-cleanup` 限定此前缀，默认只输出类型和数量，不读取值；认证通过环境变量提供。

```sh
go run ./cmd/gateway-lease-cleanup -addr 127.0.0.1:6379 -db 0
# 核对实际目标，且旧进程已排空退出、无旧版本写入后：
go run ./cmd/gateway-lease-cleanup -addr 127.0.0.1:6379 -db 0 -delete -old-process-stopped
```

清理使用分批 SCAN/UNLINK，不使用 FLUSHDB，不触及 Provider、频率和账务命名空间。SCAN 不提供并发写入的一致快照，键数量不能替代旧进程退出确认；完成后再次执行默认只读检查。

## 回退

先排空当前进程并确认退出，再启用已记录且数据兼容的回退版本。若回退版本使用另一种账务格式，不能把当前库交给它；数据库恢复或切换具有独立授权与验证要求。首次新格式安装应保留原库，不能靠清空当前库模拟回退。

源码发布、隔离测试和业务流量切换分别记录。单看镜像启动或 HTTP Shutdown 返回，不足以证明数据兼容、WebSocket 排空或账务已完成。
