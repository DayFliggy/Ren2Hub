# 单实例网关切换与回退

更新：2026-09-17。本文是单实例切换与回退的操作契约，执行结果见 [验收记录](SINGLE_INSTANCE_ACCEPTANCE.md) 和所属工作区的服务器档案。应用已在新服务器完成 PostgreSQL 隔离部署与模拟渠道验证，公网生产站点尚未上线；没有执行生产 Redis 删除或数据库恢复。现行实现不含 Redis 用户/渠道并发后端，也不支持新旧版本双活。

## 切换前记录

记录最终源码 SHA、前端构建、不可变镜像标识、当前运行版本与配置备份、数据库备份位置和回退镜像。生产流量切换前须核对 [验收记录](SINGLE_INSTANCE_ACCEPTANCE.md) 中与目标环境有关的未完成项；隔离验证通过不等于生产上线验收通过。此前协议、状态与账务迁移的原始证据保留于 [历史发布说明](archive/GATEWAY_RELEASE_PRE_SINGLE_INSTANCE_2026_09_16.md)，不能据此推导任意旧镜像可等价回退。

`gateway_runtime_v2` 保留原存储，缺少四个新字段时幂等补默认并增加一次版本；已有显式零和 false 不改。用户覆盖继续逐字段继承。历史账单、任务、状态归属和健康 epoch 不重置。

## 顺序切换

1. 完成验证与备份，前后端作为一个版本切换。遵守根工作区 `docs/workflows/SYNC_WORKFLOW.md`；发布子模块前确认其最终提交可从已授权远端取得，不能提交或覆盖其他任务的 dirty 修改。
2. 旧进程停止接收新逻辑请求并排空。默认 120 秒；新实现额外保留 5 秒强制取消后的清理期限，部署宽限期应大于两者之和并留出依赖关闭时间。HTTP、SSE 与 hijacked WebSocket 都要结束；单看 HTTP Shutdown 返回不足以证明 WebSocket 排空。
3. 确认旧进程已经退出，且没有另一个旧版本写入；不要通过删除并发键强行制造空闲。
4. 检查并清理旧并发命名空间，命令如下。
5. 启动新进程。核对 schema_version=2、实例启动时间、本地运行态、Vue 配置保存与版本冲突、JSON/SSE/Realtime、用户与渠道满载拒绝、模型转换和计费 smoke test。
6. 确认授槽减释放等于活动数、等待已退登、账务恢复积压正常，再完成发布记录。异常长持槽只报警和诊断，不强行清零。

Provider RPM/TPM、逻辑频率、健康探测、状态与账务继续依赖原有存储。某些 Redis 功能失效仍会按各自规则拒绝，不能把本地并发成功等同于整个网关不依赖 Redis。

## 旧 Redis 键清理

旧 `route:lease:v2:*` 中部分占用 ZSET 没有 key TTL，不能等待它们全部自行过期。`cmd/gateway-lease-cleanup` 只允许固定前缀，默认只输出类型和数量，不读取值。地址、DB 必须替换为已经核验的目标；认证通过 `REDIS_USERNAME`、`REDIS_PASSWORD` 环境变量传递，不放在命令行或文档中。

```sh
go run ./cmd/gateway-lease-cleanup -addr 127.0.0.1:6379 -db 0
# 仅在旧进程已排空退出并确认无旧版本写入之后：
go run ./cmd/gateway-lease-cleanup -addr 127.0.0.1:6379 -db 0 -delete -old-process-stopped
```

实际删除使用分批 SCAN/UNLINK，每批最多 256 个 key，不使用 FLUSHDB，不触及 Provider、逻辑频率和账务命名空间。SCAN 在并发写入时不是一致性快照；因此退出确认是实际删除的前提，不能由工具的键数量代替。删除后再执行默认检查，遗留键应为零。

## 回退

停止新进程接流量并按同样方式排空，确认退出后，使用记录的旧镜像与对应配置顺序启动。旧 Redis 并发状态只由重新启动的旧进程建立；不要启动第二套并发后端做在线回退。先核对新增持久化字段、状态与账务向后兼容性；未验证兼容时不能仅回退镜像。数据库恢复仍是独立授权操作。

子模块发布、根工作区同步、隔离测试部署和生产流量切换分别记录。首次部署没有旧业务版本可回退时，停止新测试栈并保留数据与证据；不将本地编译、测试或 untracked 文件称作已发布。
