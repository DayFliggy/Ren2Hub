# 单实例网关切换与回退

更新：2026-09-19。本文是单实例切换与回退的操作契约，源码验证见[验收记录](SINGLE_INSTANCE_ACCEPTANCE.md)，实际运行版本和每次部署结果由所属工作区 `docs/server/SERVER_PROFILE.md` 维护。现行实现不含 Redis 用户/渠道并发后端，也不支持新旧版本双活。

## 切换前记录

记录最终源码 SHA、前端构建、不可变镜像标识、当前运行版本与配置备份、数据库备份位置和回退镜像。生产流量切换前须核对 [验收记录](SINGLE_INSTANCE_ACCEPTANCE.md) 中与目标环境有关的未完成项；隔离验证通过不等于生产上线验收通过。

`gateway_runtime_v2` 保留原存储，缺少四个新字段时幂等补默认并增加一次版本；已有显式零和 false 不改。用户覆盖继续逐字段继承。历史账单、任务、状态归属和健康 epoch 不重置。

## 持久化兼容边界

升级与回退必须相对实际运行 SHA 核对这些结构与语义，不能仅以数据库列可被旧程序忽略判断兼容：

| 数据 | 必须保留的契约 |
| --- | --- |
| Token 转换策略与用户准入覆盖 | 仅缺失配置补默认；`safe/allow/strict`、显式 0、false 和继承值不被启动覆盖 |
| 渠道身份与健康 | 稳定凭据 UUID、端点身份版本、健康 epoch 和探测所有权继续约束请求；人工换 Key 不复用旧绑定 |
| `gateway_state_bindings` | 仅保存元数据与摘要，默认最长 30 天；未知归属或缺少 `transport_id` 的旧状态要求新会话，迁移不能补造身份 |
| `billing_recoveries` | 消费快照、资金、Token、统计与日志分别幂等恢复；未确认消费和待对账不能由旧 worker 自动退款 |
| 订阅下线后的历史数据 | 不注册或自动删除旧订阅表；非钱包恢复记录转为人工对账，非钱包任务拒绝自动结算，不转为钱包扣退 |
| 任务与 Midjourney 私有数据 | 原任务表继续承担所有权；缺少稳定凭据的旧任务不能猜测 Key；v2 图片签名域与旧链接隔离 |
| 能力快照 | 当前宿主合同为 v12，按指纹幂等重建投影；不可执行路径不能因旧快照再次开放 |

`pricing_pending`、`pricing_collect`、`usage_pending`、`usage_collect`、`reconciliation_required` 及旧 `unprepared` 的保护语义必须保持。2026-09-18 修复沿用已有列，但旧恢复 worker 不识别新的 `usage_*` 状态；不能在这些记录存在时直接回退到缺少等价保护的版本。最终用量或任务 ID 从未写入成功时不能自动补造证据，人工对账也不是数据库恢复的替代品。

订阅下线提交 `a9ee8d717f66aacc394312828f6a403232eb4ecd` 保留旧表并不意味着可直接回退：旧版本会重新开放订阅路由、支付回调和后台任务，必须重新核对历史订单及资金来源。下线后的支付处理拒绝已退休订阅订单，不能将它们作为钱包充值处理。原归档通过[Git 历史入口](../README.md#历史追溯)查阅。

迁移入口为 `model/main.go` 与 `model/gateway_config.go`，失败必须阻止实例服务。JSON 私有数据写 SQL 使用兼容字符串，读取兼容 string、bytes 和 NULL；发布前按目标 SQLite/MySQL/PostgreSQL 驱动验证，不能把某一数据库通过推及其他数据库。

## 顺序切换

1. 完成验证与备份，前后端作为一个版本切换。遵守根工作区 `docs/workflows/SYNC_WORKFLOW.md`；发布子模块前确认其最终提交可从已授权远端取得，不能提交或覆盖其他任务的 dirty 修改。
2. 旧进程停止接收新逻辑请求并排空。默认 120 秒；新实现额外保留 5 秒强制取消后的清理期限，部署宽限期应大于两者之和并留出依赖关闭时间。HTTP、SSE 与 hijacked WebSocket 都要结束；单看 HTTP Shutdown 返回不足以证明 WebSocket 排空。
3. 确认旧进程已经退出，且没有另一个旧版本写入；不要通过删除并发键强行制造空闲。
4. 检查并清理旧并发命名空间，命令如下。
5. 启动新进程。核对 schema_version=2、实例启动时间、本地运行态、Vue 配置保存与版本冲突、JSON/SSE/Realtime、用户与渠道满载拒绝、模型转换和计费 smoke test。
6. 确认授槽减释放等于活动数、等待已退登、账务恢复积压正常，再完成发布记录。异常长持槽只报警和诊断，不强行清零。

Provider RPM/TPM、逻辑频率、健康探测、状态与账务继续依赖原有存储。某些 Redis 功能失效仍会按各自规则拒绝，不能把本地并发成功等同于整个网关不依赖 Redis。

## 旧 Redis 键清理

旧 `route:lease:v2:*` 中部分占用 ZSET 没有 key TTL，不能等待它们全部自行过期。`cmd/gateway-lease-cleanup` 只允许固定前缀，默认只输出类型和数量，不读取值。地址、DB 必须替换为已经核验的目标；认证通过 `REDIS_USERNAME`、`REDIS_PASSWORD` 环境变量传递，不放在命令行或文档中。

```sh
go run ./cmd/gateway-lease-cleanup -addr 127.0.0.1:6379 -db 0
# 仅在旧进程已排空退出并确认无旧版本写入之后：
go run ./cmd/gateway-lease-cleanup -addr 127.0.0.1:6379 -db 0 -delete -old-process-stopped
```

实际删除使用分批 SCAN/UNLINK，每批最多 256 个 key，不使用 FLUSHDB，不触及 Provider、逻辑频率和账务命名空间。SCAN 在并发写入时不是一致性快照；因此退出确认是实际删除的前提，不能由工具的键数量代替。删除后再执行默认检查，遗留键应为零。

## 回退

停止新进程接流量并按同样方式排空，确认退出后，使用记录的旧镜像与对应配置顺序启动。旧 Redis 并发状态只由重新启动的旧进程建立；不要启动第二套并发后端做在线回退。先核对新增持久化字段、状态与账务向后兼容性；未验证兼容时不能仅回退镜像。数据库恢复仍是独立授权操作。

子模块发布、根工作区同步、隔离测试部署和生产流量切换分别记录。首次部署没有旧业务版本可回退时，停止新测试栈并保留数据与证据；不将本地编译、测试或 untracked 文件称作已发布。
