# 单节点切换与回退

仅一个 Ren2Hub 应用实例接业务。源码发布、隔离候选验证、正式替换分别执行；本地测试或文档更新不表示正式已经切换。具体服务器动作遵循所属工作区的同步流程与部署技能。

本轮从含业务分组的原生核心切换到渠道路由核心是全新安装：新程序在 AutoMigrate 前拒绝旧 `billing_schemas` / `billing_events` 数据库及含业务 group 字段的数据库。旧用户、渠道、Token、价格、商户、任务、工单和支付记录均不迁移；旧插件任务全部完成后，不需要携带其旧源码归档到新库。

1. 固定完整源码SHA、根gitlink、镜像ID/OCI标签、前端资源、配置、工具链及证据。未提交内容只能记 `candidate_sha=null`。
2. 同一镜像先在独立候选完成原生资金、协议、权限、任务恢复、扩展及浏览器验收；仅用本地模拟服务。
3. 停止旧入口新请求并等待所有已受理任务和在途支付归零。未归零就阻塞切换，不新造双回调入口。
4. 验证旧库备份、可读清单及配置/密钥/附件归档。保留旧数据库与旧Redis db0/db1，不删除、不原地转换、不清空。
5. 对具体的独立新数据库、另一个核实为空且与现行不同的 Redis 编号及独立附件目录及切换窗口单独取得批准后，停止旧应用并让新应用连接新目标。核对DSN、Redis编号和镜像身份，不允许新旧同时接流量。
6. 在被授权的新安装中重新完成管理员和业务配置。保留NewAPI默认价格语义，不强制清空价格。正式验证以只读身份、页面、API状态和HTTPS为主，不运行候选充值/模型驱动。

普通后续更新仍须证明数据兼容，保持原生业务配置和密钥。回退必须匹配代码、数据库和Redis目标：不能只把旧镜像接到新原生库，也不能将新应用接到旧账本库。恢复备份或切回归档库是独立数据操作，需要明确批准。所有未完成验证与回退限制保留在发布记录。
