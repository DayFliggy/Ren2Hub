# 渠道路由

2026-10-18 批准的核心以平台渠道为最小单位。业务分组及组间价格、跨组重试均退役；旧组库在迁移之前拒绝启动。NewAPI 是唯一上游，协议、认证、错误重试和任务生命周期仍以其原生实现为基础。

每个 Key 使用自动或手动模式。自动候选来自全平台，受渠道状态、模型与原生端点支持、Key 模型限制及最高渠道倍率约束。手动模式使用一份有序列表，只跳过禁用、不合格、超倍率及满载渠道；空列表返回无可用渠道，不回退自动。缓存和数据库只提供事实，由同一资格服务和选择器决策。与上游 `GetChannel` 一样，声明了请求精确模型名的渠道优先；只有这些渠道在全部规则（含 Key 倍率上限和手动列表）之后一个都不剩，才改用归一化模型名（例如去掉 `@` 修饰）匹配。预览同样按这条规则，只声明归一化名的渠道在有精确渠道可用时标为 `exact_model_preferred`。

自动排序依次为管理员 priority 降序、健康档、正权重优先且零权重备用、在途负载桶、延迟档、同档按权重产生请求内次序。负载桶为 0、1–3、4–7、8–15……；不按并发上限计算百分比。全部权重为零时等概率。低优先级不会因健康或延迟越过高优先级。

健康观察仅记录实际发送的尝试，按渠道、实际模型、操作及流式类型隔离。健康档来自按“渠道×实际模型（经 model_mapping 后）”计数的熔断：连续失败 5 次打开，打开时降到最差档；冷却 1 分钟后半开，权重乘 0.3；半开期间连续成功 3 次闭合，失败一次重新打开。上游返回 429 并带 Retry-After 时，整个渠道在这段时间内降到最差档，最长 5 分钟。熔断和冷却只降档、不剔除渠道，手动列表不读这份状态。错误率 EWMA 只保留在快照中供观测；延迟档仍按至少 50 个样本、3 秒/10 秒分档。流式请求以第一个有内容的事件为成功界，非流式取完成结果。客户端取消、满载、参数和资金拒绝不计供应商失败。观察、熔断和冷却都只在进程内，5 分钟过期，观察表和熔断表各自最多 1 万键，满时先删过期项再删最久未更新的一项并限频记日志。配置发布会失效观察，旧配置在途尝试完成后也不能填回新观察。

prefer 模式的会话亲和在亲和渠道合格时直接使用；渠道被禁用、满载或不在当前候选中时退回正常选路，不报错。非 AdvancedCustom 渠道遇到 `/v1/responses/compact` 时，按与运行时相同的端点能力判定在选路阶段跳过。重试轮次找不到候选时，返回上一次真实的上游错误，HTTP 中继和 Responses WebSocket 一致。

用户及渠道并发默认 0 表示无限，仍统计在途数，不排队。删除渠道或硬删除用户后，空闲的并发表项移除，仍有在途许可的表项在最后一个许可释放后移除；同 ID 新渠道沿用在途计数并按新上限准入。用户槽覆盖逻辑请求及其重试；渠道槽覆盖一次真实尝试及资源清理。热更新保留活动计数，Release 幂等。用户满立即 429；渠道满扫描下一候选，全部合格渠道满时 429，无合格渠道则路由不可用。

发送顺序为认证解析、用户占槽、选渠道、渠道占槽、资格与倍率复核、原生估算预扣、发送、观察与结算释放。每个逻辑调用只有一个 BillingSession；不使用信任免预扣，更贵重试须先有余额补足。模型基础价乘绑定渠道倍率一次，在原生最终取整前应用。任务保存提交倍率，后续配置不改变既有费用。见[资金实现](../billing/IMPLEMENTATION.md)。

Responses WS 按每次 create 重新认证、资格检查及占槽，空闲连接不占；不在连接内换渠道。Realtime 占整次连续会话。异步任务只在提交或实际轮询 HTTP 时占渠道槽，不在后台等待期间持槽。已接受任务遵守原渠道例外，不因 Key 偏好变化重放到其他渠道。

主要接点为 `service/route_candidates.go`、`service/channel_select.go`、`service/concurrency.go`、`service/route_attempt.go`、`service/billing_session.go`。接口与版本冲突见[网关 API](GATEWAY_API.md)，不恢复 `/api/next` 或第二套路由管线。
