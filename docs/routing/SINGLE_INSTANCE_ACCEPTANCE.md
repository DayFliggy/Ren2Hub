# 网关验收边界

本页只定义网关与协议验收的判定边界，不记录执行结果。现行行为见[统一路由](UNIFIED_ROUTING.md)和[支持矩阵](GATEWAY_SUPPORT_MATRIX.md)，复验命令见[验证步骤](GATEWAY_VALIDATION.md)，账务复验见[账务复验](../billing/VALIDATION.md)。部署版本、执行报告和验收证据只在所属工作区[服务器档案](../../../docs/server/SERVER_PROFILE.md)维护；需要旧报告时从 Git 历史读取，不把旧版本结果当作当前代码已重测。

## 判定规则

一次验收结论必须绑定实际源码 SHA、运行镜像、数据库类型、Redis 是否配置及测试条件。服务器源码、隔离测试进程和常驻业务进程可能是不同版本，分别记录，不能互相替代。

缺少环境变量而跳过的测试不算通过。本地 httptest、SQLite、miniredis、模拟上游和隔离子进程只证明各自边界；真实供应商、运行中的二进制、部署容器停止信号与宽限期需要独立证据。浏览器用例使用 API fixture 时不等同于真实后端验证。

文档整理只检查文档、引用和差异，不算重新执行应用测试。验证条件变化时重新选择所需测试，不将历史通过泛化为新版本通过。

## 尚未由现有回归证明的边界

- 当前仍为单实例，排到 A 后不会因 B 后来空闲而迁移。没有跨渠道供应商池、自适应容量或每轮 WebSocket 槽。
- [准入核心基准](../../tests/admission-benchmark/README.md)只比较 FIFO 准入与旧 Redis 核心，旧完整应用没有可重建的等价基线。它不证明完整 HTTP 路径的吞吐变化、长期固定到达率容量、真实供应商兼容性或所有部署条件下的 SSE/Realtime 排空。
- 未配置 Redis 时 Provider RPM/TPM 计数只存在于当前进程，重启清零；额度相关验收须在同一进程生命周期内完成，并单独确认重启后的行为是否可接受。
- 微基准和本地负载不代表跨主机数据库、真实网络或生产容量。
