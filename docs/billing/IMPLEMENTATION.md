# 计费重构实施记录

基线：`83bd7c23daa610b3a8c9544a1cb28bb89b6e650f`。本次按全新部署实现，不迁移旧账务数据、不清空数据库、不部署应用。

## 接受的契约

- 钱包唯一资金来源，Token 是消费上限；SQLite、MySQL、PostgreSQL 和单实例契约保留。
- 明确单价、高级安全表达式、显式免费；不可变价格版本与发送报价。
- 金额为 int64 quota，500000 quota/USD，API 整数字符串；只在最终总额舍入，正费用最低 1 quota。
- 发送前预留，重试补足，实际超预估记欠费，未知接受或用量保留对账。
- 钱包、Token、稳定事件及持久化消费结果同事务；用户可见可用、预留、已结算金额。
- 全部资金入口归于统一事件；计费表达式不读取任意正文或请求头。
- Root 对账、用户预留及流水、恢复指标和前后端回归共同验收。

实现入口：`pkg/billing` 负责规范用量和纯计价；`model/billing_event.go` 唯一写入账户投影；`model/billing_recovery.go` 提供 Reserve/IncreaseReservation/Settle/Release 及事务入口。正数入账与差额调账通过 `ApplyWalletAdjustment` / `ApplyWalletAdjustmentTx` 进入同一事件，不保留独立余额写入路径。

消费结果使用现有恢复记录作持久化待投递记录。事件与钱包、Token 同事务；日志、统计和缓存可以重建。SQL 日志按事件 ID 幂等，ClickHouse 未知写入保持保护。任务接受、终态和账务意图保持事务关联；人工金额继续驱动同一任务费用和消费结果。

已删除旧模型倍率 API/同步、运行时动态取价、无持久化资金来源、拆分钱包/Token 退款、内存资金批量写入和统计队列。历史默认价格表只服务离线初始目录转换；不再成为请求计费来源。自定义工具调用是否计费也依据冻结报价。

UI 展示最多保留小数点后 3 位；金额字符串、BigInt 运算、编辑/提交、快照及导出保持完整精度。钱包与 Token 分别显示可用、在途预留和已结算消费，无限 Token 可用额度为 null。
