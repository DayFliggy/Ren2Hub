# 结算兜底与恢复

账务按“先计费”处理：每个请求都以结算或释放结束，不存在等待人工处理的状态。钱包与有限 Token 的预留执行 `available -= R; reserved += R`；结算实际费用 C 执行 `available += R-C; reserved -= R; used += C`，超出预留的部分形成欠费。准入与 NewAPI 一致：可用额度须覆盖输入估算，输出费用在结算时补扣，因此余额为正时准入的请求可能结算为轻微负数；欠费期间后续付费请求停止准入。无限 Token 不限制可用预算，但记录 reserved 和 used。

## 结算依据

请求结束时按以下顺序取证据，管理员日志的 `admin_info.usage_billing_path` 标明实际依据：

1. 供应商用量完整且终态成功：按实际用量结算（`Usage.Confirmed()`）。
2. 用量不完整、缺少终态或包含本地计数：按观察到的用量估算结算（`Usage.Settleable()`），快照保留 `estimated` 标记；预扣倍率只作用于发送前估算，不进入估算结算。
3. 用量无法表达价格或计价失败：按该次尝试发送前持久化的冻结估算结算，日志路径为 `frozen_estimate`，`admin_info.billing_fallback_reason` 记录固定原因码。包括按次或图片计数价格缺少确认完成、Token 价格只有时长或字符计数、表达式出错、用量非法、金额超过单请求上限，以及消费证据无法落库。
4. 请求以错误结束：已交付有效输出或异步任务已被接受时按第 2、3 步结算；没有输出且没有任务 ID 时释放预留，包括发送后的 5xx、超时与连接重置。

Realtime 会话保存累计用量快照；会话无法给出最终计价时，优先按最近一次累计快照结算，再退回冻结估算。异步任务成功但完成用量无法计价时按提交时估算结算；明确失败、轮询超时或缺少上游任务 ID 时标记失败并释放。Midjourney 的上传与已完成提交经同一终态流程立即结算，超时规则与其他任务相同。

## 恢复任务

恢复任务每 30 秒处理超过 300 秒未更新的记录，在途请求由心跳刷新。已保存结算或释放意图时重放相同金额和事件；资金已提交但日志或统计未完成时只重试投递。尚未写入派发记录的请求未发送，直接释放；已派发但未结束的请求先按 Realtime 累计快照结算，再按冻结估算结算，没有估算时释放。等待供应商终态的异步任务由任务轮询负责。

结算意图在准备时解密求值证据并重放同一计算器；最终资金事务只核对证据指纹与金额，保证已接受的意图在进程重启后仍能完成。所有资金变动经不可变事件幂等，重复执行不会重复扣款或释放。报价或估算证据无法解析、身份不符或不能重放时保持恢复积压；证据损坏不能当作“从未发送”自动释放。

## 观察与处置

Root 通过 `GET /api/gateway/metrics` 查看 `billing.settlements_total`（`confirmed`、`estimated`、`frozen_estimate` 计数，进程级）和 `billing_recovery`（超时未结束记录数与最早更新时间）。积压持续不降表示恢复失败，原因在服务日志的 `billing fallback remains pending` 或 `billing consumption remains pending`。缓存、日志与统计不能作为余额来源；故障排查可读取事件与状态，不得直接 UPDATE 余额修账，调账使用管理员差额事件。

结算计数由资金事务成功后的同一出口更新，普通请求、异步任务、Midjourney 与恢复采用相同规则。重复结算、释放和回滚不增加计数，资金已提交后投递失败仍计一次。计数是进程内观测：进程退出或提交结果不明的边界可能丢失一次观测，不替代持久化资金事件。表达式失败保留固定原因码，服务日志不记录可能包含请求正文或头值的原始异常。

SQL 日志使用事件 ID 唯一键。ClickHouse 先保存写入意图，结果不明时按事件 ID 查询确认；查不到且已有写入意图时保持待投递，不盲目重写。关闭展示日志不会删除资金流水。

## 运行边界

schema 5 只允许空库安装或版本及 `EvidenceKeyID` 匹配的重复启动，必须保留显式配置的稳定 `CRYPTO_SECRET`。冻结估算与结算意图的重放依赖同一密钥和 Go 工具链；升级 Go 或回退版本前先排空网关并确认 `billing_recovery.pending` 为 0，否则无法重放的记录会停在积压中。启动还会检查旧数据：存在 `reconciliation_required` 等不支持的 `status`、退役的 `pricing_pending` / `pricing_collect`，或 `settled` / `refunded` 的 `consumption_state` 不是 `pending` / `completed` 时拒绝启动，不改资金或记录。须先用原版本完成这些记录后再升级；新版不重新开放人工对账，也不把旧状态自动解释为扣款或退款授权。当前受支持的在途记录继续由自动恢复处理。发布与回退遵循[单实例发布契约](../routing/GATEWAY_RELEASE.md)。
