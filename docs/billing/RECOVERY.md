# 任务、计费与切换恢复边界

普通请求采用 NewAPI BillingSession：按预扣与实际费用差额结算，失败按原生退出路径退款。请求内幂等状态不等于跨进程持久化资金事件。钱包、Token、日志和统计不是一个原子事务；不得在日志失败时自行重发请求或重复调账。

异步任务使用原生 `tasks` 私有数据、生产插件版本与轮询机制，完成用量由插件 ABI 和原生任务计费处理。终态 CAS、防止重复完成、退款与调整语义以 `model/task.go`、`service/task_polling.go` 和 `service/task_billing.go` 为准。保留任务引用的插件版本和源码，不以当前活动版本替代已受理任务；候选中验证重启后的查询及产物访问。

本轮全新安装不导入旧任务或支付记录，因此不需要移植旧执行快照、加密求值证据或旧插件源码归档。切换前必须先在旧应用完成所有已受理任务和在途支付。未归零时停止切换，继续由旧程序处理；不得用双回调入口、人工改数据库状态或新库补造记录绕过门槛。

GMPay 回调与人工补单用同一数据库事务保护最多一次入账。创建请求结果不明时保留 `unknown`，不重新向网关创建；已验签的晚回调仍按原单应到账额度和商户版本结算。独立新库没有旧订单，旧商户凭据也不导入。原生其他支付方式遵循其自身订单和通知合同。

备份包含数据库、应用配置、密钥及附件/任务产物存储。常规升级先核验兼容性；本轮去分组核心切换必须使用独立新数据库、另一个核实为空的 Redis 编号及新附件目录，保留旧数据库、db0/db1 和旧附件。切换和恢复分别需要明确批准，步骤见[发布契约](../routing/GATEWAY_RELEASE.md)。

返利的充值入账、来源唯一记录及奖励在同一原生数据库事务内提交；无奖励的已归因来源也保存跳过原因，不因之后开关变化补发。管理员正向加余额与全额转入使用各自业务幂等标识，不扩张成通用账本。应用停止前应完成在途订单与任务；不得以删库、清 Redis 或重放供应商请求补救不确定状态。
