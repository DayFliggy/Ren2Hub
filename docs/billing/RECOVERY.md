# 任务、计费与切换恢复边界

普通请求采用 NewAPI BillingSession：按预扣与实际费用差额结算，失败按原生退出路径退款。请求内幂等状态不等于跨进程持久化资金事件。钱包、Token、日志和统计不是一个原子事务；不得在日志失败时自行重发请求或重复调账。

异步任务使用原生 `tasks` 私有数据、生产插件版本与轮询机制，完成用量由插件 ABI 和原生任务计费处理。终态 CAS、防止重复完成、退款与调整语义以 `model/task.go`、`service/task_polling.go` 和 `service/task_billing.go` 为准。轮询使用当前注册表中该平台的插件，并把任务受理时记录的插件版本作为 `producerVersion` 传给插件，由插件按版本处理已受理的任务；候选中验证重启后的查询及产物访问。

普通更新保留既有任务、支付记录和插件注册表；候选通过旧镜像生成合成在途任务，再切换新镜像验证恢复与产物兼容。不得重新提交已受理任务或补造资金记录。新安装不导入其他核心的任务或支付记录。

GMPay 回调与人工补单用同一数据库事务保护最多一次入账。创建请求结果不明时保留 `unknown`，不重新向网关创建；已验签的晚回调仍按原单应到账额度和商户版本结算。普通更新保留原订单及绑定的商户凭据版本。原生其他支付方式遵循其自身订单和通知合同。

备份包含数据库、应用配置、密钥及附件/任务产物存储。普通更新先核验兼容性，继续使用相同 PostgreSQL、Redis 和附件目标，不重新初始化配置；独立新数据库与空 Redis 仅用于首次安装。切换和数据恢复是不同操作，步骤见[发布契约](../routing/GATEWAY_RELEASE.md)。

返利的充值入账、来源唯一记录及奖励在同一原生数据库事务内提交；无奖励的已归因来源也保存跳过原因，不因之后开关变化补发。管理员正向加余额与全额转入使用各自业务幂等标识，不扩张成通用账本。应用停止前应完成在途订单与任务；不得以删库、清 Redis 或重放供应商请求补救不确定状态。
