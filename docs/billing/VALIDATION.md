## 性能对比

相同机器、SQLite 内存库、单写连接、8 个账户、每轮 160 个请求，每种并发度运行 3 轮；完整执行预留、结算、统计及日志，逐账户核对已消费与余额。Redis 两版均关闭。基线位于独立 worktree，使用 [基线测试附件](fixtures/billing_performance_baseline_test.go.txt)，当前测试为 `model/billing_performance_test.go`。

三轮中位数：

| 指标 | 基线 1 并发 | 新版 1 并发 | 基线 8 并发 | 新版 8 并发 |
| --- | ---: | ---: | ---: | ---: |
| 请求/秒 | 813.48 | 911.83 | 770.86 | 830.52 |
| p50 毫秒 | 1.041 | 1.000 | 10.121 | 9.133 |
| p95 毫秒 | 2.121 | 2.013 | 14.058 | 14.550 |
| SQL/请求 | 34 | 32 | 34 | 32 |
| Redis/请求 | 0 | 0 | 0 | 0 |
| 连接池等待次数/轮 | 0 | 0 | 2221 | 1438 |
| 累计连接池等待毫秒/轮 | 0 | 0 | 792.525 | 1336.046 |

首次新版对比曾出现明显退化：8 并发吞吐中位数 562.28 请求/秒、p95 20.946ms。账户行锁查询改为仅取资金投影与版本字段后，吞吐恢复到 830.52，SQL 保持 32。移除旧全局账务锁后，等待更多体现在单写连接池中；连接池累计等待不等于端到端延迟，也不能用来推断 MySQL/PostgreSQL 行锁等待。8 并发 p95 比基线中位数增加约 3.5%，新版三轮 14.159–15.096ms，基线 13.338–14.283ms，应保留观察。

这些结果只覆盖本地账务/投递负载，不含上游网络、价格求值、跨主机数据库、Redis 命中或长期存储增长，不能代替生产容量压测。复跑：
