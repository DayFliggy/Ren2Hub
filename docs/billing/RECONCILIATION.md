# 恢复与人工对账

钱包与有限 Token 的预留执行 `available -= R; reserved += R`。结算实际费用 C 执行 `available += R-C; reserved -= R; used += C`；超预估允许产生欠费，下一次付费请求停止准入。无限 Token 不限制可用预算，但记录 reserved 和 used。确认未发送或明确拒绝可释放；未知是否接受、缺用量、断流或进程退出本身不能证明免费。

恢复任务读取主数据库的持久化状态。已有结算/释放意图重放相同金额和事件；资金事务成功但日志失败时仅重试投递。异步任务提交成功保持预留，收到终态才结算或释放；已知任务终态但费用无法计算，保存任务终态和待对账证据，停止重放上游。Realtime 保存累计用量和报价，累计补预留失败时停止继续生成，最终使用累计用量按所选 NewAPI 计价模式计算和舍入。

Root 在控制台“账务对账”处理：

1. 打开记录，核对请求 ID、钱包、Token、冻结报价、各次尝试与时间、规范用量、费用分项及历史事件。
2. 若金额已确认，只是事务或日志投递失败，点击重试。重试不重新请求上游，也不读取新价格。
3. 若接受状态或金额未知，保留预留并核对供应商记录。人工结算必须已有持久化配置报价、真实尝试绑定、完整实际用量和可重放加密证据；填写的 quota 必须等于冻结证据重算金额。金额和说明不能代替缺失事实。确认无需收费或明确放弃收费时可以选择释放，填写具体理由。
4. 保留操作 ID 处理网络重试。409 表示版本或内容冲突，重新加载，核对别人或恢复任务已做的决定；不要自动更换 ID 重复扣款。
5. 核对资金事件、钱包与 Token 的预留清零、任务费用、日志及统计金额一致。日志仍不可用时保留待投递状态，继续重试投递。

已结束记录不可用新操作重写。人工结算与自动恢复在同一请求锁上串行，只有一方产生最终资金事件；最终资金事务重新验证冻结证据、金额和指纹，保留已知任务关联和渠道归属。证据不足的人工结算返回 409，不能强制扣款。

详情 API 的 `audit` 使用冻结 Quote 与 Usage，并解密 AES-GCM/HKDF 求值证据后重跑同一计算器。它检查请求、真实 attempt、配置哈希及阶段绑定、报价与用量哈希、消费指纹和最终资金事件，状态为 `verified`、`mismatch`、`invalid_evidence` 或 `unconfirmed`。动态参数、请求头和时间按已保存环境结果重放，不读取当前请求或现行价格。身份、内容或金额不一致时保持待处理；相同最终 quota 不代表不同证据可以互换。API 不返回请求上下文明文或证据密文。

详情的 `audit` 与 `upstream_cost` 区分客户实收、上游成本与利润。实收按最终账本事件确定，不能用舍入前 `ChargeResult.total_usd` 代替。Root 可在详情成本表单为已结束请求的各次尝试登记账单或供应商回执，记录不可变且幂等；完整成本及已确认实收都具备时才展示利润，否则为 `null`。登记成本不改客户资金；相同表单重试保留同一事件 ID，包括写入成功但读取失败。详情展示 `base_usd`、渠道调整与调整后总额，并保留冻结审计证据。接口与冲突语义见[账务 API](API.md)。

SQL 日志使用事件 ID 唯一键。ClickHouse 先保存写入意图，结果不明时按事件 ID 查询确认；查不到且已有写入意图时保持待对账，不盲目重写。关闭展示日志不会删除资金流水。缓存、日志与统计不能作为余额来源。

指标查询失败明确显示不可用。`idempotency_conflicts` 是当前进程累计计数；`debt_events` 来自不可变流水。预留总额来自钱包，不能把 Token 预留再加一次。等待时间包括仍在途和待处理请求，应结合状态判断。当前实现保留单实例契约；SQLite 单写连接与有界锁冲突重试，MySQL/PostgreSQL 使用统一行锁助手。

## 发送与任务故障边界

任务或其他有副作用的生成请求已接受、或接受状态不明时，本地落库失败、缺任务 ID、断流和进程退出都不能证明未消费。保留预留及发送保护，不重放生成，不制造成功消费记录。已观察到有效输出时，即使后续维护失败也不能释放预算。

Replicate、Dify 的上传是生成前置操作。`UpstreamPreparationOnly` 仅表示生成尚未发送；此前失败可以释放生成预留，但已创建或接受不明的上传不可自动重放。生成发送前清除此标记，新尝试不能继承。进程退出后仍依据持久化证据恢复，不能根据缺少最终记录推断可退款。

Realtime 累计用量不是已确认最终用量；缺失终态或最终持久化失败时保持待对账。待确认与待对账记录计入积压，但不能挤占可自动恢复记录的处理批次。最终用量或任务 ID 从未成功持久化时，恢复器不能补造证据。

`relay/channel/openai/relay_realtime.go` 记录已转发的 `response.create` 数，以及已追加、提交或创建但尚未归入响应的输入；新响应出现时消费一个待处理生成和当前待处理输入。会话结束时，只有无错误、无进行中响应、无剩余待处理生成或输入、用量全部来自完整的上游观察且未混入估算、每个响应终态均为 `completed`，观察才标记为完整；否则为 `Terminal=unknown` 并保留预留。同一响应 ID 的重复 `response.done` 按状态与用量证据去重，证据冲突或已完成响应之后再出现非终态事件时直接报错，不重复累加，也不覆盖已记录的证据。

schema 5 只允许空库安装或版本及 `EvidenceKeyID` 匹配的重复启动。必须保留显式配置的稳定 `CRYPTO_SECRET`；密钥丢失或替换会阻止旧证据验证，不能重新生成密钥绕过。发现旧格式数据库立即报错，既不迁移也不清空；发布与回退遵循[单实例发布契约](../routing/GATEWAY_RELEASE.md)。故障排查可读取事件与状态，不得通过直接 UPDATE 余额修账。
