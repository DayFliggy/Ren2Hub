# 仪表盘统计范围与数据可见性

仪表盘沿用现有纸纹背景、棕色强调、手绘边框和中英文消息来源，不引入另一套 UI 组件或权限系统。

## 页面与范围

| 内容                     | 普通用户               | 管理员 / Root          |
| ------------------------ | ---------------------- | ---------------------- |
| 自动路由                 | 可见，读取现有模型目录 | 同左                   |
| 概览、统计数据           | 个人                   | 个人 / 全站切换        |
| 余额、加赠、余额可用天数 | 个人                   | 只在个人视图展示       |
| 系统状态                 | 现有全站快照           | 同左，不随用量范围变化 |

“个人 / 全站”放在 `PageHero` 标题行右侧的 actions 槽，复用 `SegmentedToggle`，支持键盘方向键、选中态和读屏名称。窄屏自然换行。自动路由不受统计范围影响，在该页签隐藏切换控件。

默认个人；选择只存在本页内存，不写 localStorage。概览与统计共享范围；热力分布、模型分布、Token 趋势、按小时、同比全部同步。范围、账号或角色变化时取消旧请求并清除已加载数据，统计页签未显示时也清除其缓存。账号或角色变化恢复个人视图；迟到的旧响应不能覆盖当前结果。全站数据源关闭时保持未知，不回退为管理员本人用量，也不伪造全站余额。全站概览隐藏余额与加赠卡片后，首行由两列热力分布与一列系统状态组成三列，Token 趋势与模型分布卡片扩展为三列满宽。

## 充值加赠卡片

卡片采用日夜光学毛玻璃风格。辅助文字最低 `0.75rem`，窗口及来源标题为 `0.8125rem–0.875rem`，主比例随卡片宽度在 `1.75rem–2.25rem` 内变化。按卡片容器而非屏幕宽度切换布局：窄于 `22rem` 时主值与水位尺分行、窗口名和比例在上、用量与进度在下；宽卡恢复横向排列。说明与金额允许完整换行，不用省略号隐藏计费信息，窗口采用内容驱动的等高网格，不固定行高。设置入口始终保留至少 `44×44px` 热区。

有加赠时主舱展示下一笔入账的服务端加赠比例（如 `+5%`）、7 格叠加封顶水位尺和全局／个人来源。下部窗口展示已计入消费 USD、距更高档的差额、比例条与加赠百分比。四格进度分割不代表配置档位数。选中窗口只由服务端 `winner_window` 决定，通过强调浅底、均匀细边框和 `aria-current` 表达。原始比例与实际比例都为零时隐藏无意义的水位尺与封顶线；若仍有个人窗口，保留全部真实进度，零加赠且无更高档时不宣称“已达最高档”。

完全无加赠、无个人窗口且没有单笔入账阶梯时，使用独立的“按本金到账”玻璃面板，展示说明与 `0%`，删除全零来源明细和空轨道。此状态不推断管理员是否配置规则，也不暗示未来必然解锁加赠。有全局加赠但无个人窗口仍展示真实来源。加载与请求失败继续使用各自状态；启用的数据源读不到时接口返回错误，卡片显示加载失败，不显示 `0%`。

`frontend/tests/visual/bonus-card.spec.ts-snapshots/` 保存回归截图；390px 中文有加赠与按本金到账的日夜截图均采用零像素容差。浏览器验证还覆盖 320/390/768/1280/1440/1920px、中英文、260–560px 独立卡片容器、200% 文字放大、长金额、权限及状态边界，检查文字下限、无遮挡、无溢出和对比度。`tests/local/core.spec.ts` 在独立后端保存加赠配置，再验证真实接口、封顶、个人窗口、刷新与 Root 配置入口；模拟 API 视觉检查与真实后端集成分别记账。

卡片直接展示本人 `GET /api/user/topup-bonus` 的完整响应，含义是下一笔入账除单笔阶梯外的加赠比例。全局加赠拆分固定加赠与全站阶梯，两者之和用精确十进制相加；个人阶梯按服务端 `winner_window` 标记当前采用项，比例取服务端 `personal_rate`。叠加值取服务端 `raw_rate`，主比例始终使用服务端 `applied_rate`，触发上限时在顶栏显示封顶胶囊。单笔入账阶梯取决于本金，只以 `amount_tiers` 列出可达档位，不计入主比例。阈值比较和差额使用 BigInt，百分比保留配置支持的四位小数精度，不把微小加赠舍入为 0。空窗口只表示当前没有适用窗口，不推断未配置或透露 shadow、排除名单。

自定义配置入口为 Root 的“系统设置 → 计费 → 充值加赠” `/system-settings/billing/topup-bonus`。卡片的设置图标仅在 Root 且 `admin` 能力开启时显示，复用同一路由。该页支持固定加赠、总上限、单笔入账阶梯、全站与个人日/周/月阶梯、各表的关闭/观察/启用模式和排除用户；每表最多 10 档，可配置阈值和加赠率。时区由 API 配置保存，现有页面不编辑时区。当前没有逐用户特约加赠，排除名单也不是个人特价表。详细规则见[充值加赠](../billing/TOPUP_BONUS.md)。

## 服务端合同

| 接口                          | 最低角色 | PAT scope                                           | 数据范围               |
| ----------------------------- | -------- | --------------------------------------------------- | ---------------------- |
| `GET /api/data/self/summary`  | 普通用户 | `usage:read`                                        | 固定鉴权用户 ID        |
| `GET /api/data/summary`       | 管理员   | `log:read`                                          | 所有用户历史聚合       |
| `GET /api/user/model-catalog` | 普通用户 | `profile:read`；带 `token_id` 时另需 `routing:read` | 现有公开渠道和模型目录 |

两个 summary 入口都禁用 HTTP 缓存。不接受 query 中的 user_id 或 scope 来扩大范围；范围由已鉴权路由显式构造，空 scope 与无效个人 ID 拒绝查询。时间上限、时区、比较区间、数据开关、额度十进制字符串与个人接口一致。

请求数、用量、Token 来自 `quota_data`；耗时与成功率来自 `LOG_DB`，两者可以位于不同数据库。全站汇总不连接 `users`，包含 Root 及删除账号留下的历史。成功率按 `user_id + request_id` 去重，某用户的成功不能抵消另一用户的同名失败请求；保留原有跨截止时间重试结算规则。响应没有账号 ID、用户名、Key 或渠道明细。不新增缓存、价格来源或账务表。

## 系统状态卡片

系统状态卡片对所有登录用户开放，读取 `GET /api/user/system-status`（`service/dashboard_system_status.go`，路由登记在 `router/extensions.go`）。接口只接受会话、拒绝 PAT，禁用缓存，每个用户每分钟最多 30 次。

- 资源：CPU、内存、磁盘各带 `state`、`percent` 和绝对容量。超过阈值为 `warning`；阈值关闭时为 `unchecked`，读数保留、按中性色显示；资源监控关闭时为 `disabled`，显示“未启用”。前端按占比显示空闲、正常、关注三档，警告档只来自 `state`。档位颜色由 `frontend/src/utils/loadTone.ts` 一处计算，Root 运维页的资源仪表共用。
- `storage_status`：取主库、独立日志库和已启用 Redis 的探测中最差的结果，取值 ok、critical、stale、unknown；主库没有检查结果时为 unknown。探测名称、原因、延迟、阈值数值、进程和连接池只在 Root 的 `/api/performance/*` 返回。
- 负载：宿主机平均负载和逻辑核数，最高只到关注档。
- 成功率：最近 24 小时，所有调用方共享 60 秒缓存（失败缓存 10 秒），`state` 区分 ok、no_requests、disabled、error；查询超过 3 秒时返回不缓存的 error，资源读数照常返回。成功率不参与标题胶囊的判定，胶囊只反映本实例的健康检查。
- 流量：`traffic` 带 `scope`、`inbound_mbps`、`outbound_mbps`、`bucket_seconds` 和 `points`，方向按服务器视角（入站为宿主 rx 或连接 Read）。来源是宿主网卡还是主监听器由部署配置决定，见[安装](../installation/DOCKER.md)；Root 的 `/api/performance/stats` 另带 `interface` 和 `reason`。

## 可见范围的边界

summary 两个入口、工单和私有路由按鉴权用户 ID 与角色隔离。下列原生接口保持上游行为，风险见[原生回归的行为变化](../upstream/NATIVE_B388_DISCLOSURES.md)：

- `/api/log/self/stat` 按用户名匹配统计，含 `%`、`_` 的用户名或改名可能汇入其他用户的数据。
- 管理员的用户列表、日志明细和旧用量接口沿用原生的可见范围，不排除 Root。
- 不带身份维度的全站聚合包含 Root 用量，这是经营统计口径。
