# 仪表盘统计范围与数据可见性

2026-11-02 按用户要求设计并实施。OpenCode 的 `hjm-g/gemini-4-argon` 参与只读交叉审计。沿用现有纸纹背景、棕色强调、手绘边框和中英文消息来源，不引入另一套 UI 组件或权限系统。

## 页面与范围

| 内容                     | 普通用户               | 管理员 / Root          |
| ------------------------ | ---------------------- | ---------------------- |
| 自动路由                 | 可见，读取现有模型目录 | 同左                   |
| 概览、统计数据           | 个人                   | 个人 / 全站切换        |
| 余额、折扣、余额可用天数 | 个人                   | 只在个人视图展示       |
| 系统状态                 | 现有全站快照           | 同左，不随用量范围变化 |

“个人 / 全站”放在 `PageHero` 标题行右侧的 actions 槽，复用 `SegmentedToggle`，支持键盘方向键、选中态和读屏名称。窄屏自然换行。自动路由不受统计范围影响，在该页签隐藏切换控件。

默认个人；选择只存在本页内存，不写 localStorage。概览与统计共享范围；热力分布、模型分布、Token 趋势、按小时、同比全部同步。范围、账号或角色变化时取消旧请求并清除已加载数据，统计页签未显示时也清除其缓存。账号或角色变化恢复个人视图；迟到的旧响应不能覆盖当前结果。全站数据源关闭时保持未知，不回退为管理员本人用量，也不伪造全站余额。全站概览隐藏余额与折扣卡片后，首行由两列热力分布与一列系统状态组成三列，Token 趋势与模型分布卡片扩展为三列满宽。

## 充值折扣卡片

沿用用户于 2026-11-02 选定的日夜光学毛玻璃风格，并按后续要求优化响应式与无优惠占位。辅助文字最低 `0.75rem`，窗口及来源标题为 `0.8125rem–0.875rem`，主倍率随卡片宽度在 `1.75rem–2.25rem` 内变化。按卡片容器而非屏幕宽度切换布局：窄于 `22rem` 时主值与水位尺分行、窗口名和比例在上、用量与进度在下；宽卡恢复横向排列。说明与金额允许完整换行，不用省略号隐藏计费信息，窗口采用内容驱动的等高网格，不固定行高。设置入口始终保留至少 `44×44px` 热区。

有优惠时主舱展示下一笔充值的服务端实付系数与减免比例、7 格叠加封顶水位尺和全局／个人来源。下部窗口展示已计入消费 USD、距更高档的差额、比例条与减免百分比。四格进度分割不代表配置档位数。选中窗口只由服务端 `winner_window` 决定，通过强调浅底、均匀细边框和 `aria-current` 表达。原始优惠与实际优惠都为零时隐藏无意义的水位尺与封顶线；若仍有个人窗口，保留全部真实进度，零优惠且无更高档时不宣称“已达最高档”。

完全无优惠、无个人窗口且没有单笔充值阶梯时，使用独立的“原价充值”玻璃面板，展示说明与服务端系数，删除全零来源明细和空轨道。此状态不推断管理员是否配置规则，也不暗示未来必然解锁优惠。有全局优惠但无个人窗口仍展示真实优惠来源。加载与请求失败继续使用各自状态；启用的数据源读不到时接口返回错误，卡片显示加载失败，不显示原价。

`frontend/tests/visual/discount-card.spec.ts-snapshots/` 保存本轮响应式设计的回归截图，替换此前固定尺寸附件基线；390px 中文有优惠与标准计费的日夜截图均采用零像素容差。浏览器验证还覆盖 320/390/768/1280/1440/1920px、中英文、260–560px 独立卡片容器、200% 文字放大、长金额、权限及状态边界，检查文字下限、无遮挡、无溢出和对比度。`tests/local/core.spec.ts` 在独立后端保存折扣配置，再验证真实接口、封顶、个人窗口、刷新与 Root 配置入口；模拟 API 视觉检查与真实后端集成分别记账。

卡片直接展示本人 `GET /api/user/topup-discount` 的完整响应，含义是下一笔充值除单笔充值阶梯外的折扣。全局折扣拆分固定优惠与全站阶梯，两者之和用精确十进制相加；个人阶梯按服务端 `winner_window` 标记当前采用项，比例取服务端 `personal_rate`。叠加值取服务端 `raw_rate`，最终 `factor` 与 `applied_rate` 始终使用服务端值，触发上限时在顶栏显示封顶胶囊。单笔充值阶梯取决于订单金额，只以 `amount_tiers` 列出可达档位，不计入卡片系数。阈值比较和差额使用 BigInt，百分比保留配置支持的四位小数精度，系数直接展示精确字符串，不把微小优惠舍入为原价。空窗口只表示当前没有适用窗口，不推断未配置或透露 shadow、排除名单。

自定义配置入口为 Root 的“系统设置 → 计费 → 充值折扣” `/system-settings/billing/topup-discount`。卡片的设置图标仅在 Root 且 `admin` 能力开启时显示，复用同一路由。该页支持固定优惠、总上限、单笔充值阶梯、全站与个人日/周/月阶梯、各表的关闭/观察/启用模式和排除用户；每表最多 10 档，可配置阈值和优惠率。时区由 API 配置保存，现有页面不编辑时区。当前没有逐用户特约固定折扣，排除名单也不是个人特价表。详细规则见[充值折扣](../billing/TOPUP_DISCOUNT.md)。

## 服务端合同

| 接口                          | 最低角色 | PAT scope      | 数据范围               |
| ----------------------------- | -------- | -------------- | ---------------------- |
| `GET /api/data/self/summary`  | 普通用户 | `usage:read`   | 固定鉴权用户 ID        |
| `GET /api/data/summary`       | 管理员   | `log:read`     | 所有用户历史聚合       |
| `GET /api/user/model-catalog` | 普通用户 | `profile:read` | 现有公开渠道和模型目录 |

两个 summary 入口都禁用 HTTP 缓存。不接受 query 中的 user_id 或 scope 来扩大范围；范围由已鉴权路由显式构造，空 scope 与无效个人 ID 拒绝查询。时间上限、时区、比较区间、数据开关、额度十进制字符串与个人接口一致。

请求数、用量、Token 来自 `quota_data`；耗时与成功率来自 `LOG_DB`，两者可以位于不同数据库。全站汇总不连接 `users`，包含 Root 及删除账号留下的历史。成功率按 `user_id + request_id` 去重，某用户的成功不能抵消另一用户的同名失败请求；保留原有跨截止时间重试结算规则。响应没有账号 ID、用户名、Key 或渠道明细。不新增缓存、价格来源或账务表。

## 已知问题修复边界

- `/api/log/self/stat` 按鉴权用户 ID 统计额度、RPM 和 TPM，用户名只作为展示字段。包含 `%` 或 `_`、改名及用户名复用都不能扩大个人范围。
- 管理员用户列表、搜索及分页总数使用同一层级约束，只返回低于自身角色的账号。Root 保留所有角色；搜索参数不能放宽约束。前端筛选项与该范围一致。
- 管理员读取使用日志列表、导出、相关统计以及旧用量接口的带身份数据时排除 Root。旧 `/api/data/users`、`/api/data/flow` 和指定 username 的 `/api/data/` 同样执行排除。Root 保留完整视图。
- 排除 Root 时先从主库获取包含软删除记录的 Root ID，再对日志库应用参数化条件；不跨库 JOIN。主库查询失败返回错误，不能退化为开放查询。
- 不带身份维度的全站聚合仍包含 Root 用量。这是经营统计口径，不表示管理员可读取 Root 明细。审计日志继续遵循既有规则。本次不改变订单、工单、异步任务等其他管理功能。
