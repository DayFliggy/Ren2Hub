# 仪表盘统计范围与数据可见性

2026-11-02 按用户要求设计并实施。OpenCode 的 `hjm-g/gemini-4-argon` 参与只读交叉审计。沿用现有纸纹背景、棕色强调、手绘边框和中英文消息来源，不引入另一套 UI 组件或权限系统。

## 页面与范围

| 内容                     | 普通用户               | 管理员 / Root          |
| ------------------------ | ---------------------- | ---------------------- |
| 自动路由                 | 可见，读取现有模型目录 | 同左                   |
| 概览、统计数据           | 个人                   | 个人 / 全站切换        |
| 余额、折扣、余额可用天数 | 个人                   | 只在个人视图展示       |
| 系统状态                 | 现有全站快照           | 同左，不随用量范围变化 |

“个人 / 全站”放在 `PageHero` 标题行右侧的 actions 槽，复用 `SegmentedToggle`，支持键盘方向键、选中态和读屏名称。窄屏自然换行。自动路由不受统计范围影响，在该页签隐藏切换控件。

默认个人；选择只存在本页内存，不写 localStorage。概览与统计共享范围；热力分布、模型分布、Token 趋势、按小时、同比全部同步。范围、账号或角色变化时取消旧请求并清除已加载数据，统计页签未显示时也清除其缓存。账号或角色变化恢复个人视图；迟到的旧响应不能覆盖当前结果。全站数据源关闭时保持未知，不回退为管理员本人用量，也不伪造全站余额。全站概览隐藏余额与折扣卡片后，首行由两列热力分布与一列系统状态组成三列，Token 趋势与模型分布卡片扩展为三列满宽。

## 定价折扣卡片

视觉以用户于 2026-11-02 提供的日间、夜间附件为准，390px 视口中的中文卡片为 `358×348px`。外层融合双色径向微光与玻璃表面令牌；主舱左侧展示最终倍率与减免比例，右侧为 7 格叠加封顶水位尺，下方两行分别展示全局折扣构成与个人最高优惠。下部日、周、月窗口各高 `41px`，同时展示窗口名、已计入消费 USD、距更高优惠档的差额（或已达最高档）、比例条与减免百分比。条内四格为视觉分割，不代表配置档位数。选中窗口由服务端 `winner_window` 决定，使用强调浅底和均匀细边框，并通过语义列表与 `aria-current` 表达状态。

附件原图保存在 `frontend/tests/visual/discount-card.spec.ts-snapshots/`。`discount-card.spec.ts` 对 390px 中文日夜卡片作零像素容差比较；同时检查桌面、320px 窄屏英文、权限、空态和对比度。`tests/local/core.spec.ts` 在独立后端保存折扣配置，再验证真实接口、倍率封顶、个人窗口、刷新与 Root 配置入口。模拟 API 的附件回归与真实后端集成分别记账。

卡片直接展示本人 `GET /api/user/usage-discount` 的完整响应。全局折扣拆分固定优惠与全站阶梯；个人阶梯按服务端 `winner_window` 标记当前采用项。个人比例是封顶前的最高窗口优惠，最终 `factor` 与 `applied_rate` 始终使用服务端值，触发上限时在顶栏显示封顶胶囊。各优惠相加后封顶，不相乘，也不将三个个人窗口相加。阈值比较和差额使用 BigInt，百分比保留配置支持的四位小数精度，倍率直接展示精确字符串，不把微小优惠舍入为原价。空窗口只表示当前没有适用窗口，不推断未配置或透露 shadow、排除名单；`unavailable` 单独说明个人统计不可用、当前只用固定优惠。

已有自定义配置入口为 Root 导航“用量折扣” `/usage-discount`。卡片的设置图标仅在 Root 且 `admin` 能力开启时显示，复用同一路由。该页已支持固定优惠、总上限、全站与个人日/周/月阶梯、各表的关闭/观察/启用模式和排除用户；每表最多 10 档，可配置阈值和优惠率。时区由 API 配置保存，现有页面不编辑时区。当前没有逐用户特约固定折扣，排除名单也不是个人特价表。本次不新增另一套折扣配置。购买额度的充值折扣是支付设置中的独立选项，不参与本卡片合成。详细规则见[用量折扣](../billing/USAGE_DISCOUNT.md)。

## 服务端合同

| 接口                          | 最低角色 | PAT scope      | 数据范围               |
| ----------------------------- | -------- | -------------- | ---------------------- |
| `GET /api/data/self/summary`  | 普通用户 | `usage:read`   | 固定鉴权用户 ID        |
| `GET /api/data/summary`       | 管理员   | `log:read`     | 所有用户历史聚合       |
| `GET /api/user/model-catalog` | 普通用户 | `profile:read` | 现有公开渠道和模型目录 |

两个 summary 入口都禁用 HTTP 缓存。不接受 query 中的 user_id 或 scope 来扩大范围；范围由已鉴权路由显式构造，空 scope 与无效个人 ID 拒绝查询。时间上限、时区、比较区间、数据开关、额度十进制字符串与个人接口一致。

请求数、用量、Token 来自 `quota_data`；耗时与成功率来自 `LOG_DB`，两者可以位于不同数据库。全站汇总不连接 `users`，包含 Root 及删除账号留下的历史。成功率按 `user_id + request_id` 去重，某用户的成功不能抵消另一用户的同名失败请求；保留原有跨截止时间重试结算规则。响应没有账号 ID、用户名、Key 或渠道明细。不新增缓存、价格来源或账务表。

## 已知问题修复边界

- `/api/log/self/stat` 按鉴权用户 ID 统计额度、RPM 和 TPM，用户名只作为展示字段。包含 `%` 或 `_`、改名及用户名复用都不能扩大个人范围。
- 管理员用户列表、搜索及分页总数使用同一层级约束，只返回低于自身角色的账号。Root 保留所有角色；搜索参数不能放宽约束。前端筛选项与该范围一致。
- 管理员读取使用日志列表、导出、相关统计以及旧用量接口的带身份数据时排除 Root。旧 `/api/data/users`、`/api/data/flow` 和指定 username 的 `/api/data/` 同样执行排除。Root 保留完整视图。
- 排除 Root 时先从主库获取包含软删除记录的 Root ID，再对日志库应用参数化条件；不跨库 JOIN。主库查询失败返回错误，不能退化为开放查询。
- 不带身份维度的全站聚合仍包含 Root 用量。这是经营统计口径，不表示管理员可读取 Root 明细。审计日志继续遵循既有规则。本次不改变订单、工单、异步任务等其他管理功能。
