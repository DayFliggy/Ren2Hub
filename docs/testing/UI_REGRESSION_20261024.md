## 覆盖清单与证据等级

最初清单中的 39 个 `views` 和 212 个 `components` 合计 251 个 Vue 文件，历史差异为 136 个未改、108 个修改、7 个新增。实际枚举 `frontend/src/**/*.vue` 还发现 `App.vue` 与 `features/task-plugins` 下 27 个 Vue 文件；完整清单必须包含这额外 28 个文件，总计 **279 个 SFC**。额外文件原本已有产品入口或应用生命周期，不是新增业务能力。

汇总入口为 [`scripts/testing/ui_coverage.py`](../../scripts/testing/ui_coverage.py)。它枚举当前 SFC，与历史 Git blob 比较，并将以下证据分别记录，不能互相替代：

- `visible-passed`：有可见组件截图，且关联 Playwright 用例实际通过、无重试；不表示该组件所有状态通过。
- `visible-current`：在上述条件外，截图记录的该 Vue 文件 SHA256 与汇总时源码一致，全部分帧截图存在。
- `visible-unverified`／`visible-unverified-source`：截图存在，但用例状态或源码归属仍未确认。
- `mounted-only`：Vue 实例已挂载，但未证明截图时可见；隐藏弹窗不算可见覆盖。
- `missing`：没有对应运行证据。路由可达性、导入关系及单测直接引用仅用于寻找场景，不计为浏览器覆盖。

`captureUI` 在实际页面读取 Vue 实例、可见 DOM、视口及滚动区域；内滚动区分帧截图，保留用例 ID、语言、主题、组件源码摘要与截图文件名。单测引用只表示源码引用，汇总脚本不会据此推断单测执行或通过。动态路由模板的静态关联仅作候选，最终入口以浏览器 URL 和实际路由解析为准。

在应用仓库中对指定的**当前源码测试产物**重跑：

```sh
python3 -B scripts/testing/ui_coverage.py \
  --evidence /absolute/path/to/current-complete-run \
  --evidence /absolute/path/to/additional-component-run \
  --output /absolute/path/to/report/ui-coverage
```

输出为 `.json` 和 `.md`，逐文件包含历史状态、路由／导入位置、单测引用、实际截图 ID、缺口和后续场景分类。`--require-visible` 在任一 SFC 缺少匹配当前文件摘要的通过用例可见截图时返回非零。该检查不等于完整矩阵、像素一致性或真实后端验收。不要把历史／修复前产物作为当前覆盖根传入，也不要用缺少测试 ID 的旧同名用例猜测执行归属；报告会保留这种歧义。

## 基线与比较边界

正常页面目标矩阵为 390×844、1024×820、1440×900 × 浅／深 × 中文／英文；断点、短屏、默认字号、键盘、中文输入法、加载／失败／重试、权限和弹窗等另有行为场景。固定浏览器、语言、时区、时间、随机种子和仓库字体；截帧使用 reduced motion 与禁用截图时的 CSS 动画，但正常动效应有独立行为断言。
