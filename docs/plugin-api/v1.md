# Ren2Hub 任务插件 v1 合同

本文件与 [v1.d.ts](./v1.d.ts)、[v1.schema.json](./v1.schema.json) 对应本地宿主实现。初始来源为上游固定快照 `d04c118c8803f49e0c9bab74dcf5b5efeab9464a`；2026-10-02 从 NewAPI `1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5` 增量适配豆包 Flash、逐模型用量和 Images 协议。2026-10-03 运行时由 sobek 换为上游 moejs `v0.1.0-alpha.3`，宿主与内置插件按文件收敛到 `1a4166d8e`；2026-10-07 随 NewAPI `b48b74ab7` 升到 `v0.1.0-alpha.5`，请求构建类钩子、`parseBatchResult` 与 openai_video renderer 的返回值直接解码为宿主结构，用量钩子仍只经数值边界校验。带本地补丁的内置插件使用 `<上游版本>+ren2hub.N` 版本号，已发布版本的源码不改写。`compatibilitySchema` 与原子终态资金恢复为本地合同。本地安全、计费和不可变身份合同优先。Schema 约束数据形状；URL、路由命名空间、模型归属、必需钩子及跨字段关系还须通过宿主校验。

## 模块与元数据

插件是单文件同步 ECMAScript 模块。禁止 imports、`require`、`async`、`await`、`fetch`、文件系统和环境访问。必需导出：

| 导出 | 合同 |
| --- | --- |
| `meta` | `apiVersion: 1`；key、名称、版本、author.name、models 和 fetchMode 必填 |
| `buildSubmitRequest(ctx)` | 返回 HTTP 请求描述符；不能直接发送请求 |
| `parseSubmitResponse(ctx, response)` | 返回私有 taskId，可附 taskData、state 和 immediate；不得返回 clientResponse |
| `parseTaskResult(ctx, body, response)` | 返回规范状态、进度、实际计数和可选 state、finishTime |
| `buildQueryRequest(ctx)` | fetchMode 为 `per_task` 时必需 |
| `buildBatchQueryRequest(ctx, tasks)`、`parseBatchResult(ctx, body, response)` | fetchMode 为 `batch` 时必需 |

key 最长 30 字节，匹配 `[a-z0-9][a-z0-9_-]*`；版本使用 semver。models 必须是无首尾空白的名称，按 ASCII 大小写折叠后不可重复。channelTypes 只声明支持的旧提供商类型；Task Plugin 和 New API 类型不能放入此字段。New API 渠道通过 `task_extend_plugin_keys` 绑定多个声明支持 `new_api` 的插件。

`description`、用量描述及标签可用字符串，或带非空 `en` 的语言映射。`website` 为无凭据的 HTTPS URL；author.url 为 HTTP(S) URL。`meta.icon` 是图标名或文本，最长 128 字符，不接受 URL/data URI；上传请求的独立 `icon` 字段承载 SVG/PNG data URI，上限 512 KiB。

`usageProfiles` 为指定模型提供完整用量字段集合，不与默认 usageSchema 合并。一个模型只能由一个 profile 拥有。模型定价与显示必须选择相应 profile；不允许把其他模型支持的分辨率等维度推断为当前模型可用。

每个 profile 可选 `compatibilitySchema`，只声明已发布但不再适合展示为当前能力的用量事实。其字段类型、单位和枚举规则与 `schema` 相同，不得与当前字段重名。编辑器和 examples 仅展示当前 `schema`；运行时校验、已有表达式预览、价格资格与冻结报价使用宿主统一派生的两者并集。新增或修改的表达式仍按当前 schema 校验，旧表达式保留既有兼容保存规则。未声明事实必须拒绝，缺失兼容字段不能自动补零。冻结 schema 和插件源码不会随新版本改变。

`retainResult?: boolean` 只允许声明在原生 submit/dynamic 路由，默认保留；显式 false 仅作用于立即终态结果。异步任务忽略该值、保留恢复数据并记录告警。协议对象中的 `retainResult` 一律作为未知字段拒绝。OpenAI Images 的立即终态由宿主自动清理持久化正文，当前内存响应用于一次性交付；后续任务和 artifact 检索返回 404。Responses 的 sync、stream、background 均保留结果。URL/Base64 下载失败或客户端断开均不重发上游生成请求、不撤销已确认的结算。

立即任务的创建、终态、完成用量及结算意图在同一事务提交；事务失败不留下可被超时退款的待处理任务，已有发送证据进入冻结估算恢复。事务提交后资金和指标交付失败保留待恢复意图，不重复发送；无法重放冻结估算时保持恢复积压，不猜测费用。正文清理不删除完成用量、结果摘要和资金证据。

## 路由与模型身份

`meta.routes` 声明已认证的提供商原生路由，提交及动态路由指定 native decode/render，查询路由只指定 render。路由必须通过保留命名空间、参数和模型关系校验。插件不能覆盖宿主管理接口或任意抢占 HTTP 路径。

`meta.protocols` 可声明 `openai_video`、`openai_image`、`openai_responses`。Responses 明确声明 `stream`、`sync`、`background` 能力；宿主拥有连接、SSE 帧、状态机及错误信封。插件协议不能模拟原生 Responses WebSocket。

解码器接收 `body.kind` 联合类型：json、form、multipart、none。文件仅以 `request_file:<field>` 或同字段后续文件 `#<index>` 的引用传入；原始二进制归宿主管理。返回 submit intent 包含 model、action、requestBody、可选 originTaskIds；query intent 包含 taskIds。

宿主按精确名、渠道别名和 ASCII 大小写合同解析模型。别名循环或跨插件歧义拒绝。共享宿主端点可以接受多个提供商候选；渠道确定后，在报价之前固定实际插件并重解码。后续报价、发送及重试都以该固定身份重新校验资格，不可重新选择另一插件。客户端 model 用于授权与响应回显，`upstreamModel` 用于提供商请求和能力判断。

originTaskIds 由宿主验证同一用户和 Token、模型权限、原始渠道及凭据身份。Suno continuation 还验证成功的 MUSIC 任务及 clip 归属。插件收到验证后的公开 ID 与私有 upstreamTaskId 映射，不能自行绕过归属检查或失败后切换渠道。

无符合条件的插件渠道返回 503，说明该任务模型需要可用插件渠道。客户端响应不暴露插件 key；管理员可按 request ID 查询包含候选 key 的诊断日志。

## 不可变执行与删除

路由 generation 是节点内的不可变快照，新请求固定一个 generation。执行持久化身份为 `{key, version, source_hash}`，并保存包含 apiVersion、名称、作者和 generation 的 TaskPluginSnapshot。源码和 v1 用量元数据由该哈希固定；计费合同另由 Quote 的 PriceVersion 定义哈希固定，包含模型配置及派生的 usage_schema。

发送前，在资金发送状态事务中建立 TaskPluginExecution attempt 引用。版本发布、激活、引用创建和物理删除以相同 namespace 行锁序列化。新发送同时复核数据库中该版本的可用状态，防止节点缓存滞后发送已禁用版本。

接受后在同一任务持久化事务中把 attempt 引用关联 Task。上游返回任务 ID 但 Task 落库失败时按提交时估算结算；没有取得任务 ID 时释放预留。两种情况都不删除引用，也不自动重发创建请求。发送后进程退出的请求由恢复任务按冻结估算结算。

轮询、恢复、协议渲染及产物访问从数据库按固定身份加载并校验源哈希；缓存也以该三元组为键。禁止用当前 active 插件替代旧版本。缺失/损坏/不支持的版本返回明确错误，任务保持未结束，超时后按失败释放，引用保留。

禁用阻止新任务，不阻止已有固定版本的查询。覆盖层禁用时同 key 内置层仍保持隐藏，不能自动复活。上传新版本、激活旧版本均不修改已存源码。内置和 active 版本不能物理删除；存在执行或 Task 引用时同样拒绝。没有关联 Task 的 attempt 只有在资金恢复明确 settled/refunded 后才可释放。已结算但可检索产物的 Task 仍保留固定代码。管理请求中的 `force` 不能突破这些条件。

## HTTP、状态与资源边界

`buildSubmitRequest` 返回 URL、method、headers、body，或 multipart parts/fileRef。`responseType` 默认 JSON，可声明 SSE；使用 SSE 必须在 meta.submitResponseTypes 中声明。请求描述符必须继续通过宿主 URL、凭据、请求体、文件、重定向、SSRF 和渠道限制，allowedHosts 不能绕过宿主校验。

带凭据请求只允许渠道 base URL 的规范 host/port 或 meta.allowedHosts。`credentialless: true` 产物请求只允许 GET/HEAD，不允许插件 headers/body；初始 URL 和每次重定向均检查 SSRF。OAuth 和渠道认证由 Go 宿主处理，插件不获得任意凭据查找能力。不要把密钥、完整请求、上游响应或私有 URL 写入 console.log。

普通钩子默认执行上限 5 秒，单插件默认并发 8；宿主 context 可更早取消。输出 taskData 和 state 各限 1 MiB，JSON 克隆/增量状态还有深度、节点及操作数量限制。运行时为上游 moejs：`eval` 与 `Function` 构造器被禁用并抛出 EvalError，内置对象深度冻结、写入抛出 TypeError，调用深度上限 512 层，`sourceMappingURL` 注释不读取文件。JS 沙箱没有硬内存隔离；Root 上传仍必须审查源代码。允许的工具列在 HostUtils：时间、UUID、HMAC/JWT、Base64、Volcengine 签名（字段为 PascalCase，见 `v1.d.ts`）、受限 JSON clone，以及 Ren2Hub 扩展 `utils.decimal` 与 `utils.json.parseNumbers`，不包含网络 API。

接受任意 HTTP 2xx 只表示允许继续解析，必须仍取得有效任务 ID、结构与接受证据。缺失任务 ID、解析失败或提交网络超时不能伪造成功，也不自动重发创建请求；没有取得任务 ID 时释放预留，已取得 ID 但 Task 无法落库时按发送前冻结估算结算。立即结果只有 SUCCESS/FAILURE 才在本次请求内结算；其余状态按异步任务落库并进入轮询。

任务是否结束只看 status，插件对运行中任务报告的 "100%" 不会结束任务。轮询结果按上游规则分类：HTTP 404/410 表示上游任务不存在，任务立即失败并释放预留；401/403、429、5xx、网络错误、钩子故障、无法识别的状态，以及 4xx 响应中报告运行中状态，都计一次连续失败。可识别的运行中结果把计数清零；计数达到 `TASK_POLL_MAX_FAILURES`（默认 20，0 表示关闭）时任务失败并释放预留，否则由 `TASK_TIMEOUT_MINUTES` 超时清理释放。宿主自身取消不计失败。轮询间隔固定，不做退避。失败原因只记录分类和 HTTP 状态码，供应商响应细节只写服务端日志。`fetchMode: "batch"` 插件对同一插件版本和同一凭据的任务合并为一次请求，批量响应缺少的任务计一次失败。具体边界见[结算兜底与恢复](../billing/RECOVERY.md)。

`parseTaskResult` / `parseBatchResult` 返回 camelCase 的 completionTokens、totalTokens、finishTime。计数必须是有限、非负、整数且未超宿主额度上限。finishTime 是供应商实际完成时间的 Unix 秒，可省略；宿主用观察时间补缺，不使用以后账务重试时间改写。`extractUsageOnComplete` 的第二参数是宿主 TaskInfo，采用 snake_case（completion_tokens、total_tokens、finish_time），第三参数是提供商结果数据。

JSON state 独立于结果 data，用于下次轮询；无效 UTF-8 规范化后再编码，持久化尺寸按实际编码计算。`submit-sse-delta@1` 模式用小 state 存控制信息、changes 构建独立结果 body。插件不直接向客户端写 SSE。

## 用量和冻结报价

`meta.usageSchema` 与按模型选择的 `usageProfiles` 声明字段类型、单位、枚举和标签；接受 number/boolean/enum。它们报告事实，不提供权威价格，不能在 manifest 增加 source、required、minimum 或 maximum 作为收费规则。

模型配置与计算采用 NewAPI `c71eefbc`，仅通过 Root `GET/PATCH /api/option/model_pricing` 编辑。任务表达式使用原样 Expr VM，例如 `u("seconds") * 0.4`，结果直接为 USD；插件覆盖由 `billing_setting.plugin_billing_expr` 保存。共享模型的实际执行插件在选渠后固定，客户端不能选择收费提供者。插件安装不会安装默认价格，缺价拒绝，显式零有效。

宿主从实际插件、模型 profile 和所选表达式派生冻结 `PriceVersion.UsageSchema`，版本为 1。字段映射为 number/string/boolean，枚举保留为 string+enum；数值边界按单位设置。当前映射的 source 为 `completion_fact`。这是宿主的执行快照，不是管理员另行发布的价格合同；定义整体纳入配置哈希，不依赖单独的 schema hash 才能冻结。读取、预览与模拟使用同一映射，旧尝试不会随插件或模型配置改变。

`extractUsage`、`extractUsageOnSubmit`、`extractUsageOnComplete` 只报告标量事实，不计算价格。预估用于预留，完成阶段使用真实用量；缺失、null、非法、负数、越界和明确零分别校验，实际事实不能从预估补齐。非法完成事实、表达式实际引用的字段缺失或 hook 失败时，成功任务按提交时估算结算；宿主不截断越界计数来制造实际事实。Wan 3.0 的提交时长估计不代替最终真实用量。

提交前校验只检查当前模型 usageSchema 与明确兼容字段，以及 duration/seconds、n/count/image_count/sample_count/batch_count/num_images 等约定数量名；非法值在报价和提交前返回 400 `plugin_usage_invalid`，未声明的普通参数（如 Suno `continue_at` 小数）不阻断请求。用量 hook 的输入中，按源文本保留的 JSON 数字只有在出口边界能原样还原时才以 JS 数字传入，其余以源十进制文本传入，宿主不在 hook 前舍入。hook 返回的数字必须是安全整数，或最短表示不超过 15 位有效数字的非整数（`0.1 + 0.2` 会被拒绝）；其他值返回十进制文本，可用 `utils.decimal` 精确计算。宿主从不静默舍入，用量事实必须属于已声明字段。

`GET /api/option/model_pricing` 的 entry 返回 `usage_schema` 与 `plugin_variants`，用于模型定价页面展示和模拟。`POST /api/option/model_pricing/simulate` 接受草稿、实际事实样例和可选 `plugin_key`，只读计算；共享任务模型须明确模拟哪一插件。表达式仍使用原样 Expr VM，支持动态 `u()` 和时间函数。任务运行与模拟只提供插件用量事实，`param()`、`header()` 不会取得提交正文或请求头；不能为模拟额外注入实际运行不可见的输入。

请求的预扣和实际求值上下文分别通过 AES-GCM/HKDF 加密，绑定请求 ID、真实 attempt、配置哈希和阶段。恢复使用原报价与加密记录重跑同一计算器；字段、身份或金额不一致时保留待处理状态。明文请求、请求头和证据密文不向插件管理 API 或日志暴露。模型配置、舍入与工具费用详见[模型定价](../billing/PRICING.md)，证据合同见[计价接口](../../pkg/billing/API.md)。
## 终态结果、资金和恢复

终态事务以当前 Task 状态作 CAS，同时核验公开任务 ID、用户/Token、渠道、平台、私有任务 ID、凭据和端点版本、attempt、插件三元组、执行快照、模型属性及 Quote 哈希。身份改变必须拒绝，不能把其他版本产生的结果写入该任务。

事务保存规范终态、插件状态、实际用量证据、结果数据/引用、供应商完成时间，并写按 Task ID 唯一的 TaskResultEvent。事件保存固定插件身份、结果摘要、用量快照和统计 bucket。SUCCESS 即使因价格或用量缺失无法按实际计价仍是 SUCCESS，账务按提交时估算结算。

结果事件是持久化 outbox：PerfMetric 投递与 posted 标记在同一数据库事务提交。崩溃、失败回滚、并发消费者及恢复重放不能重复请求/成功/耗时统计。统计关闭或缺模型时事件仍保存，投递状态明确为 disabled。只有合法完成计数才进入输出 token 指标。

资金事件、消费日志和金额统计继续通过 BillingRecovery 独立幂等投递。后续人工 settle/refund 只处理资金决定及金额投递，不生成第二个结果事件，不修改供应商完成时间。后台分别恢复待投递结果和账务。结果渲染、产物 URL 生成或客户端下载失败只影响当前读取，不改变已经持久化的任务结果与费用。

## 产物和协议输出

暴露产物必须同时导出 `listArtifacts` 和 `buildContentRequest`。listArtifacts 从固定版本及持久化 Task.Data/state 投影稳定 key、类型及可选 mimeType，最多 64 项；不能把第二份产物列表作为权威来源。key 仅允许字母数字及 `._~-`，最长 128 字符。

buildContentRequest 接收公开 taskId、显式 upstreamTaskId、producerVersion、data/state、artifactKey、baseUrl、宿主认证及安全的 Range/条件请求头。它不是完整提交 DriverContext；不应依赖请求模型或原始用户 body。宿主只代理获准的请求方法、URL、响应和字节流。

Responses 的 SUCCESS 渲染会注入只读 `ctx.artifacts[key] = {key,type,mimeType?,url}`。url 是宿主签名地址而非供应商直链。签名绑定公开任务 ID 与产物 key、无到期时间；验证后仍检查任务、所有者与固定插件。`TaskPublicAddress` 优先，仅可回退 `ServerAddress`，不信任客户端 Host。多节点须共享 CRYPTO_SECRET；轮换使旧链接失效，日志隐藏 access 查询值。有效链接不承诺供应商永久存储。

TaskView 只包含公开 task_id、platform、status、progress、fail_reason、时间和 data；不暴露用户、Token、渠道、额度、properties、密钥或私有 upstream task ID。已知 ID 字段投影为公开 ID。openai_video.render 必须返回对象，供应商扩展字段保留，但宿主覆盖公开 id/object/model/status/progress/created_at/completed_at 并删除旧 task_id。openai_image.render 返回含有效 data 数组的对象；供应商元数据保留，空结果及 Base64 下载失败明确报错。

## 管理接口、预览与验证

Root 管理前缀 `/api/plugin/task` 提供列表、源码上传、AST preview、runtime/status、版本列表、activate、status、dryrun 与版本删除；marketplace/sources 管理市场源。渠道绑定选项另受 AdminAuth 和 task-plugin 绑定权限控制。用户任务 API 为 `POST /v1/tasks/:pluginKey`、`GET /v1/tasks/:taskId`、产物列表及 GET/HEAD 产物 content。普通 Token 读取须满足归属和模型权限；有效产物签名只授权指定任务/产物。控制台任务列表不返回 data，成功任务也不返回 result_url；结果经会话认证的 `GET /api/task/:task_id/artifacts` 按需读取，只给出签名产物地址，旧视频任务给出 `legacy_content_url`，旧 Suno 任务只给出预览所需的片段字段。

预览响应返回 meta、unresolved 和 source_hash。允许直接字面量及可证明未修改、未逃逸、无循环的局部 const 引用；复杂调用、可变别名、getter、覆盖属性和不安全引用保持 unresolved。解析有深度及节点预算，不会为了补齐字段执行代码。正式编译的元数据校验仍是上传依据。

运行状态接口展示节点 generation、数据库版本摘要、最近重建和插件错误。generation 仅节点内有效，跨节点比较 database_revision。同步先读哈希，仅为变化的版本读取源代码；编译或哈希错误必须报告，不能切换到其他版本替当前持久化任务执行。

Fixture 格式为 `{name?, hook, member?, args, expected?, expectedError?}`。本地 lint/test 及管理 dryrun 只运行同步转换钩子，不执行网络描述符。建议覆盖提交/查询/失败、用量缺失与零值、原生与宿主协议、状态尺寸、共享端点和产物请求。

仓库的 `model/task_plugin_execution_test.go` 覆盖版本引用、删除并发、发送记录回滚、重开数据库和 8 MiB 源码；方言由 TEST_MYSQL_DSN / TEST_POSTGRES_DSN 显式提供。`model/task_result_event_test.go` 覆盖终态账务、固定版本拒绝和结果投递回滚/并发；这些测试不等于常驻服务重启或部署验收。部署前仍须按所属工作区的部署流程完成真实数据库、未知接受、恢复、签名产物与资金核对。
