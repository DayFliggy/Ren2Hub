SwapFace 删除本地外层快捷分派，恢复原生请求插件 ingress 与 task-attempt 入口；插件拒绝必须发生在供应商提交、预扣及任务记录之前，并释放本地用户/渠道许可。这是恢复正常安全合同，新增回归必须通过，不登记为已知失败。

严格预扣不等于最终费用封顶。任务在供应商接收后补预扣失败，若 HTTP 尚未写入会返回 403、不保存本地任务并调用异步退款；已写流式响应则继续原生保存与结算。最终钱包差额仍按原生无余额条件扣减；不能保证供应商任务被取消、异步退款必达或最终余额绝不为负。未进行真实供应商成本或崩溃注入。

Seedream 图片计数与载荷不一致时按原预留结算，是此前已披露的原生行为，本轮没有消除多收风险。异步任务终态 CAS 与后续资金调整不构成任意崩溃下的单一持久化事务；正常并发、重复请求和升级重启验证不能替代所有崩溃窗口验证。

`known_upstream_restored` 的允许集合来自固定旧版与原生预跑的正确断言。实施后发现的漏迁移断言另行记录补证时序，仍只从未改生产的旧版与固定原生树冻结期望，不从当前失败反推允许集合。用户已批准本地修复的缓存创建用量三项正确断言已转为普通测试，冻结集合为 72 项；该阶段不带 `-race`，不代表竞争检测覆盖。编译错误、超时、skip、未知断言、意外通过、源码变化及任何 DATA RACE 都阻断。定价缓存 race 单独使用 `known_upstream_race`，仅接受冻结的函数体、源码行、调用栈与完整 goroutine 创建链，且必须真实复现；其他 race 仍阻断。日志计数竞争另以 `known_upstream_logger_race` 验收，允许零竞争时干净通过，出现竞争则每条必须精确匹配事前冻结的源码与栈；业务断言失败、未知竞争和缺少测试仍阻断。三类独立验收不扩大旧 12 项诊断和 30 项阻断名单。

候选中存在这些已确认差异时，`candidate_success` 仍为 `false`，是否满足批准的交付条件另记 `deployment_eligible`。三库普通合同、三库原生差异诊断及仅 SQLite 用例分别计数；不得把诊断中的失败节点算作普通测试通过。浏览器桩、真实隔离后端和模拟供应商 HTTP 各按其实际覆盖报告，不宣称真实外部供应商联调。

普通 `ordinary_race` 阶段另行绑定 11 组共 124 次顶层执行，选择清单由固定 SHA 约束，原始执行集合等于原 143 项减去移交日志计数诊断的 19 项。候选和发布校验器分别重算源码身份、清单、命令及原始日志；任何数据竞争、断言失败、跳过、超时或缺项均阻断。它不使用三类已知差异的允许集合。
