重复字段安全项的源码依据如下。

- 表达式 `param()` 读取原始请求中首个匹配值。非透传路径也可能将标量按最后一个值解码、重新序列化后转发。使用该字段分档的表达式会按不同于派发结果的输入计价（`pkg/billingexpr/run.go:120`、`relay/helper/billing_expr_request.go:93`、`relay/compatible_handler.go:116`）。
- multipart 图片编辑按 `size`、`quality` 的首值计价，转发会保留全部值。影响按这些字段分档的表达式及旧 DALL·E 原生尺寸、质量倍率，实际偏差取决于上游的取值规则（`relay/helper/valid_request.go:229`、`relay/channel/openai/adaptor.go:545`、`relaykit/dto/legacy_dalle_image.go:38`）。
- `pkg/requestpatch` 查找及写入嵌套成员时只命中第一份，同名副本可保留在编码结果中。启用相应补丁的渠道可能转发未经预期覆盖的值（`pkg/requestpatch/patch.go:494,521,530`）。
- HTTP 分发器检查精确拼写的模型字段，透传渠道发送原文。当上游按大小写不敏感规则绑定模型时，`model` 与 `Model` 等变体可能使选模、权限及计费判断与上游执行不一致（`middleware/distributor.go:301`、`relay/compatible_handler.go:101`）。
- Responses WebSocket 逐帧解码 `response.create` 并保留正文，透传上游可能以不同规则消费同一帧。HTTP 请求体检查无法覆盖后续帧（`relay/responses_websocket.go:1016`、`relay/responses_request.go:53`）。

本地用模拟上游的不变量测试确认了表达式参数、multipart 图片、requestpatch 嵌套改写和透传 model/Model 四条路径；真实供应商对重复键的取值、Responses WebSocket 帧和视频任务 multipart 未验证。

## HTTP 流失败后的会话亲和写回

在[同步账本](SYNC_LEDGER.md)记录的冻结点，`middleware/distributor.go` 在处理请求后根据 HTTP 状态码写回亲和。客户端已收到 200 后，即使上游最终失败，`SwitchOnSuccess` 也可能把会话绑定到最后一次尝试的渠道，或者续期原绑定。此项单独跟踪，不计入上表的冻结诊断。

复现使用真实路由 `POST /v1/messages`、启用亲和的 Claude 模型和本地模拟上游。请求设置 `stream: true` 和可命中规则的 `metadata.user_id`。处理结束后用同一会话键查看绑定：

- 开启心跳，等客户端收到 `: PING` 后让所有上游尝试返回 529。也可先发送文本增量，再返回 Claude `error` 事件。这两种情况都应保留原绑定和原到期时间，首次请求应保持未绑定。
- 正常输出并以 `message_stop` 完成时，应绑定最终接单的渠道。上游已受理、客户端读到输出后主动断开时，保留对已接单渠道的续期。
- `GET /v1/responses` 的 WebSocket 使用独立的绑定时机。上游接受首个 `response.create` 并返回 `response.created` 时即可绑定，接受之前直接返回错误应保持未绑定。

上游验收应结合最后一次尝试的受理情况和明确的协议失败事件。仅凭 HTTP 200、已记录结果或流是否正常结束，无法区分以上情况。

## 本地合同，不属于等待上游

续作倍率上限、自动与顺序路由、即时并发、路由观测、预览范围、路由表锁序是 Ren2Hub 定制，行为见[统一路由](../routing/UNIFIED_ROUTING.md)。续作只豁免所选渠道列表，超出当前 Key 上限须在占槽和预扣前拒绝。插件错误净化仅放行宿主生成的 `channel_ratio_exceeded`，不放行任意供应商错误。锁序验收必须跑真实的 MySQL 和 PostgreSQL，SQLite 不能证明行锁安全。

普通 HTTP 成功路径里，客户端断开后供应商的在途尝试继续，结束后结算一次、释放一次；不做立即取消传播和退款。

上游 #8218 给 fence/version 键加了同槽标记。生产是单实例 Redis，这个标记没有功能收益，只保持键结构与上游一致，不表示应用支持 Redis Cluster；旧的 `auth:user:version:<id>` 键成为无 TTL 残留，清理属于生产 Redis 写操作，没有授权。
